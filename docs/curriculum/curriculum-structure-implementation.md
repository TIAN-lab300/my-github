# 课程、章节与知识点先修实施说明

本轮按用户授权设定项目教学关系，覆盖现有 36 门课程、144 章、377 个候选知识点。课程清单沿用项目范围，尚未核准为北京理工大学官方培养方案；不将项目依赖当成学校选课硬限制。

## 三层对应关系

1. 课程包含章节，章节包含知识点；每个知识点在课程内恰好归属一章，377 个知识点全部分配，无重复、遗漏或跨课程错连。
2. 335 条知识点先修只连接同一课程中的具体能力。例如 C 语言的函数与参数传递→递归基础，数据结构的图表示→图遍历→最短路径与最小生成树。互相独立的知识分支没有强制串成一条链。
3. 106 条章节关系为推荐关系：某章节内存在后续章节需要的知识，不代表整章所有知识点都必须完成。章节编号用于组织目录，不直接构成先修。
4. 77 条课程关系区分“先具备相关能力”和“建议补充”；例如程序设计→数据结构，数字逻辑→计算机组成，数据结构/离散数学→算法分析。课程关系仅作基础能力说明，不凭课程名称或完成分钟判断掌握，也不要求毕业设计只能在全部选修课之后进行。
5. 21 项目录外基础单独列出，包含深度学习的线性代数、微积分、概率与 Python 等。它们没有被伪造成已存在课程、正式题库或学生已掌握记录。

全量可读设定见 [课程章节与先修清单](curriculum-relations.md)，机器可读数据为 [curriculum-relations.json](curriculum-relations.json)。其中课程及知识点名称取自现有目录，分章和具体依赖是本项目教学设计。参考的公开课程说明只支撑一般基础能力要求，不证明学校官方先修或每条项目边。

## 数据库与版本

迁移 0025 新增 curriculum_relation_versions、curriculum_course_prerequisites、curriculum_skill_prerequisites、curriculum_chapter_prerequisites、curriculum_external_requirements 五张表。复用 learning_chapters 与 learning_skill_chapters，避免再建一套章节。

默认版本 curriculum-relations-v1 保存数据哈希、项目依据与明确的未核准标记。导入前检查三层关系的端点、重复归属及拓扑循环；导入在同一事务中完成，重复导入相同版本不再写入。已存在手工章节或知识点归属冲突时中止并保留原数据，不覆盖教师内容。改变关系内容须登记新版本，不能修改已登记版本的数据文件后静默覆盖。

## 页面与路径规划

课程知识库选择课程后，新增“课程、章节与先修关系”：查看课程基础、目录外基础、逐章知识点以及每个知识点的具体先修。

对于通过课程桥接创建的目标，服务端将同课程内 required 知识点先修转换为已经审核的图谱技能依赖，并与图谱原先修合并。先修缺少映射、未选入初测、或合并后出现循环，均明确阻断；不自动猜测技能映射、不自动激活无题图谱。路径执行仍依据有效测验掌握度解锁，保留原有预算、来源、版本和确认规则。

默认课程关系版本纳入课程目标指纹，关系变化后旧预览不能直接接受。四智能体的证据输入增加课程基础与目录外基础背景，并标明这些不是学生已掌握/未掌握的证明。课程基础并不自动转为跨课程测评门槛；如需验证整课或跨课程技能，仍需相应的审核图谱、等价映射和正式题库。原来独立创建的普通目标继续使用其审核知识图谱。

## 验证与部署

最终记录：240 项测试通过（129.85 秒），前端构建通过，浏览器验证章节归属、知识点先修、课程基础及目录外数学要求，页面脚本错误为 0。正式库已备份后升至 0025 并导入全部设定，原有业务记录保持，数据库完整性检查通过；8000 已运行新版本。
