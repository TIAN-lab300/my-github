# Python 调用栈与返回过程

项目原创教学讲义，先修：函数、return 与递归基本情况。预计45分钟：阅读15分钟、画调用栈15分钟、练习测验15分钟。

## 1. 调用帧与后进先出
可以把普通同步函数调用的执行过程理解为调用栈。调用者暂时等待被调用者的结果，每次调用拥有自己的局部状态；最近进入、尚未结束的调用先返回。这里用的是教学抽象，不讨论协程和生成器的挂起机制。
```python
def c():
    return 2

def b():
    return c() + 3

def a():
    return b() * 2
```
a() 调用 b()，b() 调用 c()；c 返回2给b，b计算5返回给a，a计算10。调用进入顺序为 a、b、c，正常返回顺序为 c、b、a。

## 2. 返回地址与等待的运算
被调用函数返回后，执行回到调用表达式所在位置，再继续外层计算。对于 return n + total(n-1)，外层的加法要等递归子调用返回，不能把“进入递归的顺序”和“完成加法的顺序”混为一谈。到达基本情况只是开始回收过程，不是全部调用瞬间消失。

## 3. 不同层的局部变量
同一个递归函数的不同调用可以同时拥有不同的 n。内层改变自己的局部名字，不会自动覆盖外层同名局部名字；但不同层若引用同一个可变对象，对象的原地修改仍可能被共享观察到。

## 4. 空间与异常
嵌套深度增加通常需要更多活动调用状态。线性深度的递归，调用栈辅助空间通常随深度增长；总调用次数与最大同时活动调用数不相同。若调用抛出未处理异常，程序会沿调用链传播异常，而不是伪装成正常返回值。

## 5. 跟踪练习
画出 a() 在 c() 执行时尚未结束的调用；标记每一层等待的算式；从栈顶开始逐层计算返回值。对 total(3) 分别写出“进入顺序3、2、1、0”和“完成顺序0、1、2、3”。判断 print 在递归调用前和后时，输出顺序为何不同。函数执行时间短不代表没有调用状态，返回后通常不再保留该次活动调用帧。
