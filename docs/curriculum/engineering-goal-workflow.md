# 工程目标驱动的诊断、规划与重规划

本文件解释用户三张流程图在当前代码中的落点。正式需求、设计和技术记录仍集中在 `docx` 四份Markdown文档中。

## 学生操作

1. 进入“目标与诊断”顶部的“输入工程目标，生成学习路线”，描述成果、已有基础、工具环境和限制，例如“用C++和OpenGL渲染带纹理的旋转立方体”。
2. 使用已配置、评估并激活的模型分析；需确认允许发送目标描述与公开课程目录。没有密钥时不能声称模型已调用，可显式选择“本地OpenGL基础模板”体验基础阶段流程。该模板不是通用工程理解模型。
3. 核对课程知识点、自动补入的先修、建议成果和未覆盖能力，再确认截止日期与本目标每周分钟。系统不默默把项目特定API、平台工具或数学背景标记为已掌握。
4. 在新目标卡片检查课程推荐与缺题、缺正文情况，点击开始诊断并交卷。已有已发布题优先；模型新编情境题只进管理员草稿队列，核对后发布才能用于有效诊断。
5. 点击生成首次路径；选择本地规则或云端四智能体。缺正文或预算不足时不产出可接受方案。成功后在“我的学习路径”查看引用、诊断依据、课程章节、每日分钟和具体任务；接受前再次检查输入版本。
6. 学习后记录实际分钟、累计完成比例和困难，再用未见练习或重测题验证。分钟不会直接提高掌握度。
7. 可修改目标预算、截止日期、学习偏好，或全局每日/每周分钟和可学习日期，再主动生成重规划预览。时间调整复用已提交诊断，不把同题重做作为新证据；能力范围改变需重新解析确认。
8. 如允许系统重规划，开启目标卡片中的开关并选择模式。后端运行时约每5秒检查变化，一次处理一个目标；检测到有效证据、执行记录、预算、资料、其他目标/教师任务占用或未完成任务逾期时生成候选。系统不会自动接受候选。

## 三张图的实现对应

|流程要求|实现位置与行为|
|---|---|
|自由工程目标与能力确认|`engineering_goals`提案接口；仅接受数据库中真实知识点ID，明确目录未覆盖能力|
|课程与知识点对应|`project_goal_contexts`绑定目标私有图谱；`catalog:public-Cxx-Kxxx`直接身份映射，避免把Python与C++同名函数混用|
|先修|冻结课程关系版本，补齐知识点硬先修；对已选课程之间的硬先修排序，不把整门未测前置课程视为已完成|
|审核题库与服务端判分|使用`learning_question_versions`中已发布版本；模型新题默认draft；沿用`diagnoses → attempts → observations`和BKT|
|唯一证据桥接|`project_evidence_links`以学生+稳定题目ID去重；课程已评分作答可桥接，重复同题不再次增加BKT证据|
|四智能体|复用`GoalDiagnosisAgent → PathBuildingAgent → PlanReviewAgent → LearningReplanAgent`与现有LangGraph；云端审查最多3次修复|
|正文覆盖|逐知识点关联到真实资料版本；下载、正文片段和引用可追踪；网址和导读不冒充正文|
|日周预算与每日任务|复用全局`allocate`及`reservations`；每日日期展示具体知识任务和分钟，所有目标/教师任务共享预算|
|候选确认|沿用paths待接受状态及输入指纹；过期候选拒绝，接受时原子切换路径和预约|
|重规划历史|已完成记录只读，局部补强或全局重排；失败/拒绝保留原活动路径|

## 个人正文与公开讲义

工程目标可关联本人已确认正文。先在个人资料页上传、解析并核对内容，再在目标卡片选知识点和资料、确认使用权限。关联不改变资料私有归属；其他学生与普通教师不能因此读到它，也不会出现在其他学生的输入指纹中。新版本替换后需重新关联。没有正文的网页收藏或原始图片不能直接用作正文证据；云端处理仍单独检查`cloud_allowed`。

新增22篇项目自编C++/图形学基础讲义，覆盖C06的12个知识点及C28的10个知识点，包含解释、练习与自检，保存真实TXT版本并建立知识点关联。文本为自编基础内容，技术自检，非学校官方教材且未经授课教师审定。原文参考入口为[C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines)与[Khronos OpenGL规范](https://registry.khronos.org/OpenGL/specs/gl/glspec46.core.pdf)，不把外部规范全文下载或复制进库。

这些讲义可支持基础阶段的有效规划，不表示已具备完整的OpenGL上下文、GLSL、VAO/VBO等专项题库或完整工程验收能力。提案会显式列出未覆盖部分；项目成果还需单独验证。

## 模型、权限与数据版本

模型解析与新题生成复用服务端配置及现有60场景质量复核要求；没有密钥、模型未激活或质量不通过时明确失败，不暗中以本地规则假装云端结果。目标描述须显式同意发送；私有上传正文仍需另行授权。模型输出只用于提出候选，不执行工具命令，不自动发布图谱、题目或路径。

私有图谱不进入管理员全局图谱激活列表，也不能通过直接请求激活为全局图谱。学生确认的是所选真实课程能力范围，系统没有把两个不同课程节点按名称擅自作等价映射。原有管理员审核的课程—全局图谱映射链路仍保留。

输入指纹包含目标/预算、资料及权限、私有图谱、课程题目状态、资料关联与先修版本。已冻结的先修版本变化时，旧方案可查看但新诊断/生成要求重新解析确认；旧候选也不能直接接受。

## 安装与保留数据

```powershell
.\.venv\Scripts\python.exe scripts/apply_engineering_goals.py
```

脚本先备份数据库与附件，迁移到0028，再幂等导入22篇原创讲义。账号、班级、题目、已有诊断、测验、掌握证据、路径和预约数量保持不变。导入结果与备份位置保存在`backend/data/engineering-goals-install-result.json`。验收使用独立数据目录，通过`--data-root`指定，测试账号与题目不进入正式库。

## 验证边界

隔离测试覆盖本地工程模板、真实模型契约的测试替身、私有范围、跨课程诊断、题库审核、正文覆盖、BKT去重、每日排期、过期候选、主动与系统重规划、教师任务预算占用、拒绝失败保留原路径。浏览器验收输入、确认、出题交卷、课程推荐、每日安排、接受、自动开关、预算编辑和管理员完整题审核。

测试替身证明接口与数据流，不证明真实供应商已连通或模型教学质量已达标。本机真实模型能力仍以管理员配置后的实际调用结果为准。代码没有下载第三方课程视频，也没有实际编译运行学生的OpenGL工程。


## 保存与诊断区域补充

无模型密钥也可以填写工程目标和时间后点击“保存工程草稿”，刷新后在“已保存的工程草稿”恢复。草稿不等于已确认目标，也不自动生成路径。确认能力范围后，页面自动打开“诊断与作答”区域；答题可暂存和恢复。交卷结果中的“根据本次诊断生成学习路径”会显示运行结果，成功后查看候选并接受。已归档目标不能继续诊断、生成或重试旧运行，请新建活动目标。旧版主题入口已折叠，工程目标请使用顶部新入口。


## 没有诊断目标时如何继续

诊断区会显示本人尚未确认的草稿，点击“继续完善草稿”恢复。无模型时选择“手动选择课程知识点”，选课程并勾选相关知识点，点击“整理所选知识范围”，核对范围、截止及预算后确认，随后自动出题。这里不宣称模型已理解工程；未覆盖能力仍需补齐。已确认的目标在首次路径激活前内部状态可能为draft，但依然可以诊断；该状态不会再被排除。只有草稿或归档目标时不会出现一个无解释的禁用开始按钮。
