# teaching-v4 与可执行教学任务

## 本次修正

旧报告硬判据60/60不代表语义正确。本版本针对已定位的非唯一反推、虚构摘录/图示、快照数不一致、缺配套题目、先修只按时长前进、已掌握仍重复基础活动和预算填满问题，分别提供明确素材与结构校验。参考原逐例复查见../evidence/implementation/qwen-plus-semantic-review-20261117.md。

新版基础评价仍为60例，每主题20例；前18例覆盖目标水平3×先修状态3×有无材料2，最后两例检测缺测评素材和无须重复学习。它不是覆盖全部专业课、工程目标、长期学习效果或辅导智能体的综合实证评价。

## 管理员操作

1. 停止旧云端服务，重新通过“启动云端搜索版.cmd”启动，在本机重新输入密钥；不要把密钥写入源码或聊天。
2. 管理员→模型配置→qwen-plus→“运行新版60场景评价”。按钮会明确提示60例真实调用消耗，只有点击确认后执行。
3. 保留页面查看进度；完成后打开teaching-v4报告，逐例核对素材、模型输出与判据。未通过则修正后重评，不修改原分数。
4. 逐例确认并填写真实复核依据后批准；随后显式激活。历史teaching-v3报告不能继续充当新版激活依据。

CLI仍支持scripts/evaluate-cloud.ps1；只有同判据、同提示词哈希和同场景输入才允许复用旧响应。跨版本会重新调用，不能用旧60/60冒充新测试通过。评价素材中的答案属于明确的合成测试素材，不来自学生正式试卷。

## 学生操作

重新生成学习路径后，在任务卡“学习与测评材料”查看具体版本资料、项目补充示例、演算要求和真实新题数量。调用栈示例可展开6个事件及7个快照。示例解析不属于正式测验答案，也不直接增加掌握度。先修由服务端有效测验证据解锁。

题库不足时先阅读与示例演算，补题后重新生成/核验，不伪造可领取测验。旧路径内容保留；新材料包只随新生成候选冻结，不静默改写历史。

## 实现位置

- quality_assets.py / teaching_examples.py：明确给定的原创素材。
- quality_rubric.py / quality_evaluation.py：teaching-v4结构与语义相关判据、缓存绑定。
- quality_policy.py：统一新报告兼容性、完整性和审批状态。
- quality_jobs.py / api/models.py：管理员真实评价后台任务与进度。
- teaching_packets.py / planning.py / cloud_planning.py：任务材料、题库就绪、模型声称检查及修复。
- TeachingPacket.tsx / ModelQuality.tsx：学生材料卡与管理员评价页面。

本轮离线替身测试不等于真实qwen-plus新版已通过；逐字引用和结构正确也不能保证全部自然语言教学语义正确，仍须复核。

## 2026-11-17 管理员未达标激活策略（替代此前强制60/60门槛）

质量评价是参考依据，管理员可以选择普通“激活”（保持完整质量复核条件）或“带风险激活（无需60/60）”。后者仅要求已通过真实JSON连通性试验，管理员填写原因即可启用；允许质量报告未通过、旧版、未复核或尚未生成，不把未达标报告变成通过。

POST /admin/model-configs/{id}/activate 新增可选 allow_unqualified=true、reason 参数。服务端在model_configs.evaluation记录管理员、时间、原因、当时报告及分数、配置指纹，并记录model_activated_with_override审计。无数据库迁移。变更模型或提示词等关键配置后原授权失效；正常激活会移除特殊授权。

统一activation_state供规划模型状态、四智能体调用、工程目标分析、学习辅导使用，避免按钮激活成功后实际入口继续被旧质量门槛拦截。学生端标明模型带风险启用。API密钥、资料云端授权、引用核验、预算/先修等实际业务规则不被绕过；激活不代表每个模型输出都会被采纳。

使用：重启云端搜索版，管理员→模型配置→qwen-plus→带风险激活，输入试运行原因；学生端刷新模型状态后可选择云端规划/辅导。此项代码变更本身不自动激活生产数据库模型。
