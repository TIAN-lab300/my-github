# 首次诊断与重规划：模型、智能体和数据库协作

更新：2026-11-15。最新状态：课程桥接已按首版受控范围实施，详见 [课程桥接实施说明](course-planning-bridge.md)。下文第 5 节保留编码前设计，实施状态以新说明为准。本文区分已实现链路与待建设的专业课程桥接，不把课程目录或外链导读视为正式题库。

## 1. 职责边界

数据库保存事实和版本；业务服务组卷、判分、计算 BKT、校验先修与时间预算；LangGraph 编排四个节点；大模型根据已授权证据解释诊断、提出学习活动并审查教学合理性。模型没有数据库连接，也不能执行任意 SQL、修改成绩、发布题目或直接激活路径。

同一套四节点工作流支持本地规则与云端模型。前者不调用大模型；后者要求管理员完成连通性、60 场景质量评价、人工复核并激活配置，且服务进程配置对应密钥。四智能体是四种受约束职责，可以调用同一个模型，无需四个模型账户。

## 2. 已实现的首次诊断流程

1. 学生创建目标。`goals` 保存确认后的技能、目标版本、截止日期及预算；技能必须来自可用知识图谱。
2. `POST /goals/{id}/diagnoses` 从内置或审核题库组卷，检查目标知识点覆盖，冻结 `diagnoses.questions`、题库版本和目标版本。题库缺失就提示补齐，不用模型临时编题替代有效测评。发卷接口不返回答案。
3. 学生提交 `POST /diagnoses/{id}/submit`。服务端按照冻结答案判分，写入 `attempts` 与逐题 `observations`，保存 `diagnoses.mastery_snapshot`、`mastery_snapshots`。重复提交不重复增加证据；目标版本变化后旧诊断不能提交。
4. 学生选择本地或云端生成方案，创建 `agent_runs`。后台执行四节点，不在数据库事务中等待模型网络请求。
5. 诊断节点读取同一学生、当前目标版本的已提交诊断，构造 `learner-evidence-v1`：诊断 ID、作答 ID、题库版本、每技能诊断正确数/总题数、诊断时及当前 BKT 概率、累计证据数、最新证据 ID、先修关系与目标内的执行记录。仅包含目标及其递归先修，不发送题目答案、密码、联系方式、自由文本学习笔记。
6. 路径节点按业务规则确定待学技能，从学生有权访问的有效正文检索材料并安排学习活动。云端只接收明确允许云端使用的材料片段；外链阅读指南不是可引用的正式教学正文。
7. 审查节点同时执行确定性硬规则与云端教学审查。未通过则有限次修复，失败保留原路径。模型建议不能绕过先修、证据支持、预算和身份权限。
8. 重规划节点解释首次安排或后续调整，将结果保存为 `paths.status=pending_acceptance`。`paths.validation.learner_evidence` 冻结生成依据；`agent_steps`、运行检查点及模型调用元数据可追溯。
9. 学生接受方案时，再次核对指纹、权限、版本、预算和规则，然后在事务中激活路径、替换预约。模型生成成功不等于路径已经生效。

## 3. 四智能体的数据契约

| 节点 | 主要输入 | 输出及约束 |
| --- | --- | --- |
| GoalDiagnosisAgent | 目标、预算、已评分诊断、当前技能证据 | summary、risks；缺证据为 unknown，不能断言已掌握或确定薄弱 |
| PathBuildingAgent | 诊断解释、同一证据快照、确定的待学任务集、授权材料片段 | 技能、分钟、活动、引用版本；不得增加未知技能或虚构引用 |
| PlanReviewAgent | 学习活动、证据快照、材料、硬规则结果 | approved、issues；不能覆盖业务规则失败 |
| LearningReplanAgent | 原/新计划差异、变化触发原因、证据快照 | reason、recommendations；不得改写完成历史 |

当前 BKT 使用 `bkt-v1`：初值 0.2，掌握判定阈值 0.75，薄弱阈值 0.45。它是证据累积的估计概率，不是考试成绩或准确率。无有效答题证据单独标记 unknown；学习分钟不直接增加掌握概率。当前目标图谱掌握度汇总该学生同技能的有效 observations，包含跨班级证据，尚无时间衰减规则。

## 4. 已实现的重规划闭环

学生完成教师任务、路径测验或等价重测 → 有效答题证据更新 → 重新计算掌握度 → 目标列表提示需要重规划 → 学生请求 `POST /goals/{id}/replan-previews` → 使用当前证据重新执行四节点 → 展示差异 → 接受或拒绝。

新增比较：对比上个活动路径冻结的 learner_evidence，识别“有效测验证据变化”和“学习执行记录变化”。只读查询不改分，不因接受路径本身引起的用户水位变化而循环提示重规划。旧路径没有该快照时不推测历史差异，下一次成功规划建立基线。

其他既有触发包括薄弱技能、教师任务逾期、预算、图谱、目标版本和来源变化。预算变幅超过 30%、图谱或技能范围变化采用全局重规划；其他情况通常局部调整。已完成任务保留，掌握度下降的已完成技能使用独立补强任务；生成失败或拒绝预览保留旧路径。

接受时发现生成后又发生学习/测验、目标修改、来源变更等输入变化，返回 `STALE_PREVIEW`，要求重新生成。任务预约替换与路径激活在同一事务完成。当前不会在每次作答后自动调用收费模型；由学生确认发起预览。

## 5. 专业课程库与目标图谱尚未统一：必须显式建设的桥接

已有课程链：`curriculum_catalog_courses → curriculum_catalog_skills → learning_question_versions → learning_assessment_items → learning_responses → learning_skill_evaluations`；材料由 `learning_material_links` 关联知识点。目标规划链使用图谱技能、`diagnoses → attempts → observations → paths`。两者 ID 和题库版本体系不同，本次没有将课程测验偷偷复制进 observations。`catalog_evidence_integrated=false` 明示这一边界。

建议后续按以下顺序实施，尚未创建下述表或接口：

1. 建立 `curriculum_graph_mappings`：课程技能 ID、图谱版本、图谱技能 ID、审核状态、审核人、时间。每个课程技能在指定图谱版本最多一个已审核映射；禁止按名称相似度自动生效。多对一映射需要审核等价性。
2. 建立 `learning_evidence_links`：课程测验 item ID 唯一、目标证据 observation ID 唯一、映射版本。仅同步已提交、题目已审核且归属当前学生的有效答案。整批事务写入，唯一键保障重试不重复累计；没有映射的结果保留在课程进度中并提示未纳入规划。
3. 课程目标显式绑定 course_id、技能集合及映射版本。初次诊断以 diagnostic 题组覆盖目标技能；practice 和 retest 各有审核题，重测排除已曝光题。项目课程继续使用教师量规，不能用选择题替代毕业设计验收。
4. 统一题库适配层向现有诊断与路径测验提供冻结题目快照，保留原课程、题目、题目版本及映射来源。不能只接入初测而让后续路径测验落回无关内置题库。
5. 材料必须具有可访问、可定位、可检索正文，映射后的技能和先修关系经审核；云端授权单独校验。模型提出题目、映射或先修关系只能生成审核草稿。
6. 回填历史证据需独立的预览/确认流程，保留原始课程评分，并确定统一时间顺序重放 BKT；撤回映射或停用题目需定义证据失效与重算规则，不能直接累加两份概率。

课程接入验收必须包含：课程→技能→三阶段题库→判分→唯一证据→画像→引用正文→规划→重测→重规划全链路，以及跨课程拒绝、跨用户隔离、重复同步、撤回材料、映射变更、旧预览失效。36 门课程有目录和候选知识点，不代表都具有这些正式数据。
