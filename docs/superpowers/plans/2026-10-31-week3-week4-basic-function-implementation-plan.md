# 第三、第四实践周基础功能完善实施计划

编制日期：2026-10-31。状态：待实施；不代表功能已完成。

## 一、依据与当前起点

课程依据为根目录《卓越软件工程_第2至8周项目推进与每周汇报说明.docx》，正文标题《卓越软件工程项目实践精炼版》。第三周交付统一账号与数据约定、模块骨架、首条真实运行流程；第四周交付集成版本、各模块状态、缺口与补齐计划。

项目依据为现有 requirements-spec、technical-design（v3.2）、2026-10-28 模块深讲设计、implementation-plan-v1，以及 platform-foundation 计划。沿用学生、教师、管理员三端和 A/B 模块分工。

当前目录已发现需求设计文档、HTML 原型、汇报文件和计划；未发现可运行前后端源码。因此以“文档和原型已有，实现待建立或核验”为起点。若源码位于其他仓库，启动时先核验并复用，通过验证的部分直接转入完善，不重复开发。原型中的交互与模拟数据不算后端实现。

周次按课程实践周计，D1—D5 为周内工作日，不根据文件日期推断课程日期。A/B 为负责人占位，每人负责所属模块的页面、接口、数据和验证。

## 二、两周交付目标

第三周完成：管理员建号 → 教师建班、发布资源和任务 → 学生入班、阅读、作答 → 获得反馈 → 保存记录 → 学生查进度、教师查提交情况。全部在同一版本中操作，重启后数据仍存在；另完成一次真实模型能力试验。

第四周完成：基础模块可连续使用，接入目标、诊断、首次路径、打卡、掌握度更新、重规划及画像的最小闭环，形成可演示中期版本。智能模块限一个预置教学主题，扩展主题和复杂异常随后补齐；不得把这一切片当作最终范围缩减。

## 六、实现约束与依赖

1. 先完成账号、班级和对象授权，再接资源与任务；先保存真实学习事实，再聚合进度和画像。
2. 统一 `/api/v1` 和后端 Schema；资源、任务、作答、目标、路径都使用稳定 ID。服务器从会话确定用户，不能相信页面传来的角色或归属。
3. 先冻结预算接口再并行实现规划与重规划，避免 A 等 B 整包完成。全局预算包含所有活动目标与教师任务，不分别计算各自上限。
4. 作答、评分证据、BKT 和待处理事件需保证事务与去重；阅读完成、任务完成、知识掌握分别记录。
5. 路径区分草稿、待接受、活动、被替代和被拒绝；接受时检查掌握度和预算版本。模型只提供候选，确定性规则决定是否允许激活。
6. 画像从授权事实计算，保留版本和数据水位；刷新失败保留旧快照并标记过期，不伪造新数据。
7. 模型不可用时资源、作答、反馈、记录仍正常运行；智能页面明确失败原因。没有密钥先完成独立业务开发，真实调用列为待验证。

## 七、验证与演示脚本

准备管理员 1 人、教师 2 人、各一班、学生至少 2 人和一个预置教学主题。所有结果关联运行版本、输入和证据位置。

| 编号 | 操作 | 预期结果 | 首次验证 |
| --- | --- | --- | --- |
| V01 | 建号、登录、建班、邀请码入班 | 角色与归属正确，重复入班无重复记录 | W3 |
| V02 | 教师发布资源和任务，学生阅读作答 | 正确反馈、记录持久化，双方可查进度 | W3 |
| V03 | 跨班读取资源、任务、成绩 | 服务端拒绝且不泄露他人数据 | W3 |
| V04 | 同一作答重复提交，重启后查询 | 不重复计分，结果保存 | W3/W4 |
| V05 | 创建目标、完成诊断、生成并接受路径 | 来源可查、先修与预算校验通过 | W4 |
| V06 | 测验后更新掌握度并预览重规划 | 有真实依据；拒绝不改原路径，接受生成新版本 | W4 |
| V07 | 用旧预览接受重规划 | 返回版本冲突，不覆盖新状态 | W4 |
| V08 | 核对学生/班级画像及权限 | 数值与原始记录一致，无数据不写零掌握 | W4 |
| V09 | 模型失败、证据不足、非法上传 | 页面给出明确提示，不产生伪成功或正式路径 | W3/W4 |
| V10 | 停用账号或重置密码后使用旧会话 | 旧会话不能继续访问受保护数据 | W4 |

验证选择关键规则测试、接口集成测试和上述端到端脚本；不以页面截图代替数据库持久化、权限和跨模块验证。失败记录输入、预期、实际、原因、修复人和复测结果。

## 八、周交付与完成定义

每周汇报前24小时准备：平台完成表、本周运行版本、A/B各自成果卡、下周任务表；具体提交时间以课堂要求为准。汇报后24小时补齐反馈与行动。

建议证据目录：`docs/evidence/week3/`、`docs/evidence/week4/`，包含运行说明、版本标识、正常及异常验证记录、截图或录像入口、缺陷表、个人贡献与AI使用记录。实际实施时创建，当前不预填通过结果。

完成表字段：模块、负责人、本周承诺、实际状态、接口/页面/代码入口、验证编号及结果、证据、剩余问题、补齐日期。状态只用“完成/部分完成/未完成/待核验”；完成要求页面、接口、数据、授权和关键验证均有证据。

第三周退出门槛：首条真实教学链连续运行，数据持久化和隔离通过，每人有实现及运行结果，真实AI试验有可定位结论。

第四周退出门槛：基础模块集成可用，单主题智能闭环可演示，画像可复算，主要异常有处理，各模块状态和第五周补齐责任清楚。达不到门槛时如实标记部分完成，优先关闭流程中断、数据丢失、越权、重复评分，再处理智能效果与界面完善。
