## 1. 文档说明

### 1.1 文档目的

本文档将《智能学习规划助手项目设计方案》v3.0 转化为可实现、可追踪、可测试和可验收的需求规格。本文档规定学生 AI 学习闭环、教师端、平台权限、知识覆盖门控、联网搜索规则、数据要求、非功能指标和现场验收条件。

本文档是课程项目开发、测试、现场演示和答辩验收的共同需求基线。实现不得通过预生成路径、缓存规划响应或直接修改数据库来跳过现场闭环中的核心步骤。

### 1.2 文档适用范围

本文档覆盖十周课程项目 MVP，包括：

- 学生端学习目标和学习者画像管理。
- 基础诊断、知识缺口计算和个性化路径生成。
- 学习任务、打卡、测验证据和 BKT 掌握度更新。
- 路径重规划和原路径差异展示。
- RAG、知识图谱、约束规划、规则校验和 Agent 轨迹。
- 千问云端模型调用、原生联网搜索、Web 证据保存和来源校验。
- 单次现场连续演示六阶段闭环。
- 管理员、教师和学生账号登录及角色权限。
- 多教师、多班级、邀请码加入和班级成员管理。
- 教师班级总览、学生详情、教师任务和提交查看。

后续演进功能不属于当前版本必须交付范围。

### 1.3 术语与缩写

| 术语 | 定义 |
| --- | --- |
| Agent | 根据状态选择工具和下一步动作的智能执行体 |
| BKT | 贝叶斯知识追踪，根据答题证据更新知识掌握概率 |
| `GoalSpec` | 由自然语言目标解析得到的结构化目标规格 |
| `LearningPath` | 通过图谱和规则校验的可执行学习路径 |
| `LearnerSnapshot` | 某一时点的学习者基础、时间偏好、掌握度和证据快照 |
| `ReplanEvent` | 记录重规划触发原因、前后差异和接受状态的业务事件 |
| RAG | 检索增强生成，先检索真实课程材料再生成内容 |
| 千问云端模型 | 通过阿里云百炼/DashScope 调用的 Qwen 商业模型 |
| 原生联网搜索 | 千问模型服务在生成过程中自动检索最新公开网页的能力 |
| Web Evidence | 保存 URL、标题、摘要、发布时间、抓取时间和内容哈希的网页证据 |
| 时效合规 | 时效性声明至少有一条发布时间在请求日期前 30 天内的来源 |
| RBAC | 基于角色的访问控制，同时检查班级或学生对象归属 |
| Classroom | 单学校内由一名负责教师管理的班级 |
| Teacher Task | 教师创建的一次性任务，独立于 AI 路径节点并可计入学习负荷 |
| `verified` | 具有真实本地或联网证据，并通过来源、图谱和规则校验的内容 |
| `draft` | 缺少充分依据、只能查看或编辑、不能发布为正式路径的内容 |

### 1.4 需求优先级

| 优先级 | 定义 |
| --- | --- |
| 必须 | 不满足则不能通过课程验收，且属于现场闭环或系统可信边界 |
| 应当 | 影响完整性和使用体验，时间不足时可缩短实现范围，但不能破坏必须项 |
| 可选 | 可在 MVP 完成后实现，不影响十周基础验收 |

## 2. 产品总体描述

### 2.1 产品定位

智能学习规划助手面向计算机专业低年级学生，根据其学习目标、当前基础和时间预算，生成满足先修关系与时间约束的学习路径。系统通过诊断、打卡和测验持续更新掌握度，并在测验未达标、多次未完成任务或时间预算变化时调整路径。

系统同时通过千问原生联网搜索补充最新公开资料，通过本地 RAG 保留课程专属依据。两项证据都进入来源校验，联网结果不得仅凭模型记忆生成。

教师通过班级总览和学生详情观察学习进度，并向全班或指定学生布置独立任务。系统不是替代教师的自动教学系统，教师任务也不直接修改 AI 路径。

### 2.2 用户类别

| 用户类别 | 类型 | 主要职责 | 访问边界 |
| --- | --- | --- | --- |
| 学校管理员 | 平台管理角色 | 创建、停用和重置教师与学生账号；管理平台级配置 | 可访问学校账号管理，不默认查看学生学习详情 |
| 学生 | 核心产品用户 | 创建目标、完成诊断、接受路径、打卡、提交测验、完成教师任务、查看重规划 | 只能访问本人数据和已加入班级的教师任务 |
| 教师 | 核心产品用户 | 创建班级、生成邀请码、查看本班进度、布置和撤回教师任务、查看提交 | 只能访问本人负责班级的数据 |
| 数据与模型维护人员 | 项目次要角色 | 导入课程资料、维护图谱和题库、配置千问模型、维护 API Key、评估搜索质量 | 使用管理工具或 CLI，不作为独立教师端 |

本期实现教师端和多用户权限体系；不实现跨学校多租户、同一班级多教师协同授课、家长端和学生社交。

### 2.3 运行环境

- 操作系统：Windows 11 64 位。
- 后端服务：FastAPI 监听本机 `127.0.0.1:8000`。
- 前端：React、TypeScript、Vite。
- 数据存储：SQLite 与 Chroma。
- 云端模型：阿里云百炼/DashScope 千问 API，默认 `qwen-plus`。
- 联网搜索：千问原生联网搜索能力。
- 现场演示必须能够访问 DashScope API 和互联网，并配置有效 API Key。
- 账号认证采用本地用户名/密码和会话，不接入学校统一身份认证。

### 2.4 约束与假设

- 开发周期约 10 周，团队规模固定为 2 人。
- 平台为单学校部署，支持多教师、多班级；不提供跨学校租户。
- 管理员创建教师和学生账号，教师创建班级并生成邀请码。
- 首个管理员账号由初始化脚本从环境变量创建，不设置硬编码默认密码。
- 学生可加入多个班级；教师可负责多个班级；同一班级只有一个负责教师。
- 教师只能访问本人负责班级的数据；学生只能访问本人数据和已加入班级的任务。
- 教师任务为一次性任务，可关联知识节点，但不直接修改 AI 路径节点。
- 登录使用本地账号密码，不接入学校统一身份认证。
- 模型由千问云端 API 提供，本系统不训练、微调或部署生成模型权重。
- 现场核心演示必须联网；断网时明确失败，不得伪造最新资料。
- API Key 只由服务端从环境变量或本地密钥文件读取。
- 用户学习数据只向云端发送完成任务所需的最小内容，并在首次使用前展示隐私说明。
- 课程资料必须具有合法使用权限，支持 Markdown、TXT 和文本型 PDF。
- 扫描版 PDF 和图片 OCR 不在当前版本范围内。
- 允许预置已审核课程资料和本地索引，但联网搜索结果必须由现场请求获得。
- 时效性声明至少需要一条发布时间在请求日期前 30 天内的网页来源。
- 现场不允许使用预生成路径、缓存规划响应、固定重规划结果或预先录制的核心交互。

### 2.5 产品边界

#### 2.5.1 本期范围

- 创建、查询、更新和归档多个学习目标。
- 自然语言目标解析和目标人工修正。
- 个性化诊断、掌握度初始化和学习者画像。
- 课程资料导入、混合检索、真实引用和内容可信级别。
- 知识节点、技能节点、先修关系、题库映射和 DAG 校验。
- 路径生成、时间分配、硬约束校验、解释和候选方案。
- 学习任务、打卡、测验证据、BKT 更新和重规划。
- 千问云端模型调用、原生联网搜索、Web 证据保存、来源校验和模型配置管理。
- 四智能体协作、工具调用记录和运行轨迹展示。
- 单次现场连续演示六阶段闭环。
- 管理员、教师和学生登录与角色权限。
- 教师创建多个班级、生成邀请码和学生加入班级。
- 教师班级总览、学生详情、任务布置和提交查看。
- 教师任务计入学习负荷并触发重规划建议。

#### 2.5.2 非目标

- 不接入真实教务系统或学校统一身份认证。
- 不实现跨学校多租户、同一班级多教师协同授课、家长端和学生社交。
- 不建立自有网页爬虫或大规模网页语料库，联网公开信息由千问搜索返回。
- 不提供正式学分、成绩单或学校教务认证。
- 不训练、微调或部署生成式基础模型。
- 不保证互联网搜索结果的权威性；低可信或无时效来源只能产生 `draft`。
- 不提供断网状态下的实时更新能力。
- 不实现生产级集群、高可用和云部署。
- 不实现代码沙箱执行；代码题自动运行与判题属于后续演进。

## 3. 核心业务闭环

### 3.1 闭环定义

系统必须支持以下连续业务链：

`定目标 -> 诊断起点 -> 生成路径 -> 执行打卡 -> 证据验收 -> 重排闭环`

每个阶段必须产生结构化数据、持久化状态和可查看的 Agent 或规则处理记录。

教师端必须支持以下连续业务链：

`登录 -> 查看班级进度 -> 布置任务 -> 学生提交 -> 教师查看进度`

### 3.2 定目标

**前置条件：** 学生已进入本地系统。

**输入：** 自然语言学习目标；可选技能目标、当前基础、截止日期、每周时间、每日最大时间、学习偏好和课程资料。

**输出：** 结构化 `GoalSpec` 和目标记录。

**通过条件：** 目标可映射到至少一个技能节点；时间字段合法；约束可被路径规划器读取。

**失败处理：** 无法解析时保留用户输入，指出缺失或冲突字段，并要求补充或人工修正，不得创建可发布的正式路径。

### 3.3 诊断起点

**前置条件：** 已存在有效 `GoalSpec`。

**输入：** 目标子图、关键知识节点、题型和难度配置。

**输出：** 诊断题集合、作答记录、初始掌握度和置信度。

**通过条件：** 每个目标关键节点具有初始估计；低置信度节点被标记；题目映射到有效知识节点。

### 3.4 生成路径

**前置条件：** 已完成诊断并生成学习者快照。

**输入：** 目标、掌握度、先修关系、预计学时、时间预算、截止日期、本地数据库记录、本地 RAG 证据、按需联网搜索结果和模型候选路径。

**输出：** 知识覆盖结果、缺失项、主学习路径、候选替代方案、任务排期、风险分、解释、本地引用、联网引用、来源发布时间和抓取时间。

**通过条件：**

- 生成前存在一次可追溯的 `KnowledgeCoverageResult`。
- 非时效性且本地覆盖完整时，不得调用联网搜索。
- 除用户明确选择仅使用上传资料外，本地存在缺失项或查询涉及时效性时，必须先联网补充并重新检查。
- `verified` 节点均有真实本地或联网引用。
- 时效性声明至少有一条 30 天内的联网来源。
- 硬先修无冲突，路径无重复节点。
- 学时、每日负荷和截止日期满足约束。
- `draft` 内容不能发布为正式路径。
- 不可行时必须返回冲突原因和可行替代方案。

### 3.5 执行打卡

**前置条件：** 学生已接受路径，且任务处于可执行状态。

**输入：** 任务 ID、实际时长、完成状态、完成比例、困难程度和可选备注。

**输出：** 打卡记录、执行偏差和任务状态。

**通过条件：** 时间与完成比例合法；重复请求不重复写入；应用重启后记录不丢失。

### 3.6 证据验收

**前置条件：** 学生已选择可验收任务或知识节点。

**输入：** 题目 ID、答案、作答时间和幂等键。

**输出：** 得分、证据记录、掌握度变化、薄弱节点和是否触发重规划。

**通过条件：** 题目可映射到知识节点；评分规则可重复执行；重复提交不重复更新 BKT。

### 3.7 重排闭环

**前置条件：** 已产生新的测验证据、执行偏差或时间约束变化。

**输入：** 当前路径、最新掌握度、打卡记录、时间预算和触发事件。

**输出：** 原路径与新路径差异、变更原因、涉及证据、新完成日期和用户影响。

**通过条件：** 未完成的硬先修不被破坏；新路径不超出更新后的预算；调整必须形成 `ReplanEvent`。

### 3.8 教师干预闭环

**前置条件：** 教师已登录并负责至少一个班级。

**输入：** 班级、学生范围、任务标题与说明、截止时间、预计学习时长、可选知识节点和资料链接。

**输出：** 教师任务、学生任务分配、学生提交和教师查看状态。

**通过条件：** 教师只能操作本人班级；任务可发布给全班或指定学生；任务独立于 AI 路径；教师任务计入负荷并可生成重规划建议。

## 4. 外部接口和界面需求

### 4.1 平台页面

| 页面 | 必需内容 | 主要操作 |
| --- | --- | --- |
| 登录 | 用户名、密码和角色提示 | 登录、退出 |
| 管理员账号管理 | 教师和学生账号、状态和重置密码 | 创建、停用、重置 |
| 教师班级总览 | 多个班级、完成率、学习时长、掌握度和风险学生 | 查看班级和学生 |
| 教师学生详情 | 目标、路径进度、教师任务、掌握度、成绩、风险和提交 | 查看提交、布置补充任务 |
| 教师任务管理 | 任务内容、班级/指定学生、截止时间和预计时长 | 创建、发布、撤回 |
| 目标设置 | 目标、基础、时间预算、截止日期、偏好 | 创建或修改目标 |
| 基础诊断 | 题目、进度、预计耗时、答题入口 | 提交诊断 |
| 内容生成 | 覆盖结果、缺失项、知识框架、任务、题目、候选路径、可信级别 | 查看、编辑、重新生成 |
| 学习路径 | 节点图、学时、掌握度、先修、本地与联网引用、来源时间、锁定原因 | 接受路径 |
| 今日任务 | 任务、预计时长、关联知识、资料引用 | 打卡 |
| 教师任务（学生端） | 教师任务、截止时间、资料链接和提交状态 | 打卡、文本或链接提交 |
| 证据验收 | 题目、作答、评分和掌握度变化 | 提交答案 |
| 重规划 | 原路径、新路径、差异、原因和影响 | 接受或拒绝调整 |
| 云端模型管理 | 千问模型名、搜索开关、提示词版本、限流状态和评估结果 | 激活已通过评估的配置 |
| AI 轨迹 | Agent、覆盖检查、云端调用、联网搜索、Web 证据、耗时和校验结果 | 展开查看 |

### 4.2 API 要求

- 基础路径统一为 `/api/v1`。
- 请求和响应使用 JSON。
- 时间使用 ISO 8601，服务端保存 UTC，界面显示本地时区。
- 所有业务接口必须具有请求和响应 Schema。
- 错误响应必须包含 `code`、`message`、`details` 和 `trace_id`。
- 重复打卡、重复测验和重复接受重规划必须支持幂等。
- 前端不得直接访问 SQLite、Chroma、DashScope API 或 API Key。
- 所有受保护接口必须校验会话、角色和班级/学生对象归属。

### 4.3 模型与搜索接口

- 系统只能通过 LLM Gateway 调用千问云端模型。
- 联网搜索必须通过千问原生搜索能力发起，搜索查询和来源写入本地记录。
- 生成前必须先执行 KnowledgeCoverageChecker，并保存覆盖结果。
- 非时效性且本地完整时不得调用联网搜索；存在缺失或时效性检查时必须联网，除非用户明确选择仅使用上传资料。
- 联网证据合并后必须重新执行覆盖检查。
- LLM 输出不得直接写入业务数据库。
- 路径生成结果必须先经过 Schema、本地/联网引用、时效、图谱和约束校验。
- 每次 Agent 工具调用必须写入 `agent_steps`。
- 每次模型生成必须记录云端模型配置、搜索开关、提示词版本、请求时间和运行 ID。

### 4.4 教师平台接口

系统至少应提供：

| 能力 | 接口要求 |
| --- | --- |

### 5.2 目标和诊断规则

- 同一学生可以拥有多个目标，目标之间共享课程资料和画像，但路径、证据和重规划历史必须按目标可区分。
- 修改已生效目标的时间预算或截止日期时，必须创建新版本或触发重规划，不覆盖旧路径。
- 诊断必须覆盖目标关键节点；无法覆盖的关键节点必须标记为低置信度。
- 诊断题必须映射到有效知识节点，无法映射的题目不得影响 BKT。
- 诊断重测不得删除历史作答，新结果应生成新的掌握度快照。

### 5.3 内容、图谱和路径规则

- 模型可以生成候选知识节点、先修关系和任务，但不能决定最终路径是否可行。
- 生成计划前必须查询本地数据库、知识图谱和 RAG，并由 KnowledgeCoverageChecker 判定数据是否完整。
- 覆盖检查至少包含目标技能、知识节点、硬先修、预计学时、验收题和真实证据六类项目。
- 缺失原因必须使用结构化 `gap_type` 表示，包括目标映射、节点、先修、学时、题目、证据、时效和图结构问题。
- 非时效性目标在本地 `is_complete = true` 时不得联网搜索。
- 除“仅使用上传资料”模式外，存在缺失项或查询涉及时效性时必须联网补充；合并 Web 证据后必须重新检查。
- 用户明确选择“仅使用上传资料”时可以关闭联网，但缺失项或时效性内容只能标记 `draft`。
- “检查 -> 搜索 -> 合并”最多执行 2 轮，仍不完整时返回 `draft` 和未闭合缺口列表。
- 最新或时效性声明必须来自本次联网搜索，不能使用模型记忆或旧缓存替代。
- 每个 Web 引用必须包含 URL、标题、抓取时间和来源域名。
- 时效性声明至少需要一条发布时间在请求日期前 30 天内的来源，否则只能标记 `draft`。
- 官方文档、学校课程页和标准组织资料优先于一般社区文章。
- 硬先修子图必须是无环有向图。
- 每个可规划节点必须具有预计学时；每个 `verified` 节点必须具有至少一条真实本地或联网引用。
- `verified` 判定必须同时满足证据覆盖、来源时效和图谱规则，模型不得自行提升可信级别。
- 路径发布前必须通过 VR-001 至 VR-008。
- 路径不可行时，系统应返回冲突规则、受影响节点、超时量和至少三种可行替代方向，例如延长截止日期、降低目标范围、提高学习时间或减少扩展内容。
- 用户接受新路径后，新路径成为当前版本，旧路径保留只读历史。

### 5.4 打卡和测验规则

- 实际学习时长必须大于零；完成比例必须在 `0` 至 `1` 之间。
- 缺勤按计划任务是否完成计算，不按是否打开页面计算。
- 同一任务连续两次未完成时，应触发局部重规划判断。
- 选择题和结构化答案由确定性评分规则处理。
- 简答题允许 LLM 辅助形成评分建议，但最终得分必须由版本化评分规则或人工确认产生。
- 代码题在本期作为证据任务，不执行代码沙箱；自动编译和测试属于后续演进。
- 同一作答请求重复提交时，应返回原结果，不重复生成证据或更新 BKT。
- 多次有效作答的合并规则必须版本化并可在界面查看。

### 5.5 BKT 和重规划规则

- 默认掌握阈值如下：
  - 小于 `0.45`：薄弱，必须补强。
  - `0.45` 至小于 `0.75`：进行中，需要继续练习。
  - 大于或等于 `0.75`：达到解锁条件。
- 每次掌握度变化必须保存旧值、新值、证据、参数版本和时间。
- 低于 `0.45`、同一任务连续两次未完成、时间预算变化、证据冲突或目标范围变化时，系统应评估重规划。
- 目标技能变化、总时间预算变化超过 30%、多个关键节点持续不达标或局部调整无法满足硬约束时，应执行全局重规划。
- 重规划必须展示原路径、新路径、节点差异、触发原因、规则和证据。
- 用户拒绝重规划时，系统保留原路径并显示延期或未达标风险。

### 5.6 异常和恢复规则

- 非法 JSON 最多自动修复 2 次，仍失败时终止当前节点且不得写入业务表。
- 路径规划失败后最多重试 3 次；仍失败时返回不可行原因和替代方案。
- RAG 无有效结果时应扩展查询或降低阈值；仍无结果时标记证据不足。
- 模型超时时应保留最近成功状态，允许从当前节点重试。
- Qwen API 不可达、API Key 无效或配额不足时，应返回明确错误码和可操作提示。
- 联网搜索失败时不得静默改用模型记忆；可以保存或返回明确标注的非实时草稿。
- 云端模型配置切换失败时应回退到上一个已通过评估的配置。

### 5.7 教师平台规则

- 未登录用户不得访问学生、教师或管理员业务接口。
- 管理员可创建、停用和重置教师及学生账号，但默认不查看学生学习详情。
- 教师只能访问本人负责的班级、班级成员、教师任务和任务提交。
- 学生只能访问本人数据、已加入班级和分配给自己的教师任务。
- 邀请码必须具有有效期和最大使用次数，可被教师撤回。
- 教师任务必须包含标题、说明、截止时间、预计时长、目标范围和完成方式。
- 教师任务目标范围只能是本人班级的全部学生或该班级中的指定学生。
- 教师任务独立于 `path_items`，不得直接增加、删除或重排 AI 路径节点。
- 教师任务时长计入每日和每周学习负荷；超过上限时生成重规划建议，学生确认前原路径不变。
- 教师任务状态至少包括草稿、已发布、已撤回；学生分配状态至少包括未开始、进行中、已完成、逾期。
- 学生成功提交打卡、文本或链接后，任务分配进入已完成状态并计入教师进度；提交记录保留供教师查看，本期不要求教师审批或评分。
- 教师只能查看与班级课程或教师任务相关的答题结果和提交，不包含学生未关联本班的私人目标和隐藏备注。
- 登录失败、账号停用、班级归档、任务发布、任务撤回和越权尝试必须记录审计日志。

## 6. 数据需求

### 6.1 核心数据实体

系统至少应持久化以下数据：

- 用户和学习者画像。
- 管理员、教师和学生账号、角色和账号状态。
- 班级、班级成员、邀请码和教师负责关系。
- 教师任务、学生任务分配、提交和教师查看状态。
- 登录、权限变更、任务发布/撤回和越权尝试审计日志。
- 学习目标、结构化 `GoalSpec` 和目标版本。
- 知识节点、技能节点、先修边和题目映射。
- 课程文档、文档片段、向量索引和引用元数据。
- 诊断题、诊断作答、测验题、测验作答和评分结果。
- 学习路径、路径节点、学习任务、打卡记录和证据。
- BKT 参数、掌握度快照和重规划事件。
- Agent 运行、Agent 步骤轨迹、云端模型调用和联网搜索记录。
- 知识覆盖检查结果、缺失项、搜索轮次和判定时间。
- 生成内容、可信级别、引用和提示词版本。
- Web 证据快照、来源状态、内容哈希和时效判断。
- 千问模型配置、搜索策略、评估结果和激活状态。

### 6.2 数据完整性

- 主键使用可排序字符串或 UUID。
- 时间以 UTC ISO 8601 保存，界面转换为本地时区。
- 路径发布后不得原地修改，必须创建新版本。
- 课程文档删除采用软删除，已有路径引用仍可查看。
- JSON 字段必须通过应用层 Schema 校验。
- Web 证据必须记录查询、URL、发布时间、抓取时间和内容哈希。
- 云端模型配置必须记录提示词版本和评估结果，未评估配置不得激活。
- 用户答案日志可使用摘要或哈希，避免无必要地保存完整隐私内容。
- 发送到云端模型的数据类别和最小化范围必须写入运行记录。
- 用户密码只保存安全哈希，不得保存明文或写入日志。
- 教师任务不得写入 AI 路径表，任务分配必须指向有效班级成员。
- 教师只能访问本人班级数据，学生只能访问本人数据和分配给自己的任务。

| NFR-PERF-002 | 千问联网搜索响应 | 小于 15 秒 |

### 7.2 可靠性需求

- Agent 每个节点具有超时、失败和可重试状态。
- 应用重启后不得丢失已提交打卡和证据。
- 数据导入失败必须事务回滚。
- 重复提交必须幂等。
- 路径生成支持从最近成功节点恢复。
- 云端模型超时、限流和搜索失败时保留最近成功状态并允许重试。
- 模型配置切换失败时自动回退到上一个已通过评估的配置。
- 会话失效时清理前端身份状态，受保护请求返回 `AUTH_REQUIRED`。
- 现场演示连续运行三次不出现阻断性崩溃。

### 7.3 可解释性需求

- `verified` 节点必须显示至少一条真实资料来源。
- 联网来源必须显示 URL、来源域名、发布时间和抓取时间。
- `draft` 节点必须显示醒目标识。
- 每条路径限制必须对应规则编号。
- 每次重规划必须显示触发原因和前后差异。
- Agent 轨迹必须显示云端调用、联网搜索、工具节点、耗时和校验结果。
- 解释文本不得覆盖规则校验失败结论。

### 7.4 安全和隐私需求

- 服务默认只监听本地回环地址。
- 密码只保存 Argon2 或 bcrypt 哈希。
- 登录使用安全会话，修改数据的请求必须校验 CSRF 或同源策略。
- 所有受保护接口必须在服务端校验角色和班级/学生对象权限。
- 教师不得访问非本人班级；学生不得提交他人任务或读取他人进度。
- 管理员、教师、学生登录和关键教师操作必须记录审计日志。
- 向千问云端发送的数据必须遵循最小必要原则，并在首次使用前提示供应商和数据类型。
- API Key 只允许服务端读取，不进入前端响应、日志或 Agent 轨迹。
- 上传文件必须限制扩展名、大小和规范化路径，防止目录穿越。
- 不发送未授权课程资料、个人隐私或没有生成必要的完整答题原文。
- 日志不得记录完整密码、密钥或不必要的完整答案。
- Web 证据和模型配置必须具有版本与内容哈希。

### 7.5 可维护性需求

- 前端、API、Agent、算法和数据访问分层。
- 核心算法必须有单元测试。
- 业务接口必须有 Schema。
- 提示词、BKT 参数、千问模型配置和搜索策略必须版本化。
- API 依赖版本和评估问题集必须可复现。
- 数据导入脚本可重复执行。
- FR-001 至 FR-030 应能够映射到设计、接口、数据和测试用例。

### 7.6 可用性需求

- 学生无需开发者介入即可从界面完成六阶段闭环。
- 教师无需开发者介入即可完成班级创建、邀请、任务发布和进度查看。
- 长耗时操作必须显示当前 Agent、步骤和加载状态。
- 生成结果提供重新生成和查看原因入口。
- 错误信息必须说明用户可采取的操作。
- 桌面端为主要验收界面；手机端不在本期验收范围。
- 节点颜色不能作为唯一状态表达，必须同时提供文本或图标。

## 8. AI、联网搜索与模型配置需求

### 8.1 千问云端模型

- 默认通过阿里云百炼/DashScope 调用 `qwen-plus`，模型名可配置。
- 推理通过服务端 LLM Gateway 发起，前端不得直接持有 API Key。
- 默认启用千问原生联网搜索。
- 路径可行性由确定性算法判断，千问模型不得覆盖规则失败结果。
- 默认单节点推理超时为 90 秒，路径生成总超时为 180 秒。
- API Key、限流、配额和网络错误必须映射为稳定错误码。
- 系统不训练、微调、合并或部署生成模型权重。

### 8.2 联网搜索与时效

- 用户要求最新资料、当前版本或近期变化时，系统必须启用联网搜索。
- 每次搜索必须记录搜索查询、发起时间、来源数量和搜索状态。
- 每条 Web 证据必须包含 URL、标题、来源域名、摘要、发布时间、抓取时间和内容哈希。
- 官方文档、学校课程页和标准组织资料优先于一般博客或社区文章。
- 时效性声明至少需要一条发布时间在请求日期前 30 天内的来源。
- 来源发布时间缺失、无法访问或超过 30 天时，相关内容只能标记 `draft`。
- 搜索结果为空时允许扩展查询；仍为空时不得使用模型记忆冒充最新信息。
- 系统必须保留搜索失败和来源不可访问的记录。

### 8.3 云端模型配置

模型配置至少包含：

| 配置 | 要求 |
| --- | --- |
| 供应商 | 阿里云百炼/DashScope |
| 模型名称 | 默认 `qwen-plus`，可版本化切换 |
| 搜索开关 | 默认开启，可按场景受控关闭 |
| 搜索参数 | 结果数量、来源过滤和时效范围 |
| 生成参数 | 温度、最大输出和超时 |
| 提示词版本 | 每次运行必须记录 |
| 评估结果 | 未通过评估不得激活 |

配置切换必须保留旧版本。新配置鉴权或评估失败时恢复上一可用配置。

### 8.4 AI 与搜索质量门槛

- JSON Schema 合法率不低于 95%。
- 联网回答引用存在率必须为 100%。
- 时效性声明的 30 天来源合规率必须为 100%。
- 搜索来源可访问率不低于 95%。
- 路径硬先修冲突率必须为 0。
- 在 20 个未预先配置的目标中，至少 80% 可生成通过规则校验的路径。
- 在本地数据完整的非时效性测试目标中，联网搜索调用次数必须为 0。
- 在缺失数据测试目标中，必须识别缺口、触发搜索并在合并后重新检查。
- 搜索不可用时必须返回明确错误或 `draft`，不得伪造最新资料。

## 9. 验收需求

### 9.1 现场闭环验收

`AT-015` 是最高优先级现场验收场景。验收必须在一次连续会话中完成：

1. 确认演示数据处于可重复的初始状态、网络可访问且 API Key 有效；如系统提供一键重置，则只重置业务数据并保留课程资料、索引和千问模型配置。
2. 学生现场输入包含缺失知识项或时效性检查的新目标、截止日期、每周时间和每日时间。
3. 系统现场解析目标并生成诊断题。
4. 学生提交诊断答案，系统生成初始掌握度和学习者快照。
5. 系统先检查本地覆盖结果；存在缺失或时效性要求时调用千问联网搜索，合并后重新检查并生成知识框架、候选路径、风险和本地/联网引用。
6. 学生查看证据并接受一条 `verified` 路径。
7. 学生提交一次学习打卡。
8. 学生提交一份预先设计但不属于缓存响应的未达标测验答案。
9. 系统现场更新 BKT，展示掌握度下降、补强任务插入和后续任务顺延。
10. 学生预览并接受重规划，系统展示原路径与新路径差异。
11. 评审能够打开 Agent 轨迹，确认目标解析、联网搜索、本地检索、规划、校验、BKT 和重规划均产生本次运行记录。

**通过条件：**

- 所有步骤在单次会话中连续完成。
- 路径、重规划和最新信息来源不是预生成或缓存结果，核心请求具有现场时间戳和新的运行 ID。
- 现场能够展示覆盖检查前后结果，证明搜索由缺失项或时效性条件触发。
- 至少一个知识点展示真实本地引用，至少一个时效性声明展示本次联网来源。
- 至少一个硬先修冲突场景被规则校验阻止或修复。
- 至少一次测验未达标触发补强和重规划。
- 无阻断性崩溃、手工改库或开发者替用户操作。

## 12. 需求基线结论

本项目在约 10 周内交付一套单学校、多教师、多班级的智能学习规划平台。系统必须先检查本地数据库和 RAG 覆盖，缺失时才通过千问原生联网搜索补充，再重查、生成和校验学习计划；教师端通过角色权限和班级隔离查看进度并布置独立任务。

现场验收的核心不是单独展示页面或模型输出，而是证明系统能够在一次连续会话中，由现场输入触发目标解析、联网搜索、诊断、路径生成、打卡、未达标测验、掌握度更新、补强任务和路径重规划。任何依赖预生成搜索结果、缓存路径或人工改库的演示均不满足本规格。
