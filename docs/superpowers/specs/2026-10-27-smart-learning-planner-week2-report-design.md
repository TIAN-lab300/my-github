## 1. 设计范围

本次只设计第 2 实践周汇报，不覆盖第 3 至第 8 周的完整项目答辩。

第 2 周的任务是确认需求，不要求最终软件完成。PPT 必须集中回答四个问题：

1. 完整平台最终要做哪些必做功能。
2. 这些功能如何组成整体原型和端到端流程。
3. 每个模块怎样证明做完，而不是只展示计划和代码量。
4. 两名成员分别主责什么，本周各自能展示哪一条需求或原型。

本次不重点讲底层技术实现。云端模型、RAG、知识图谱、BKT 和四智能体只说明能力边界，不展开提示词、SQL、接口字段或算法公式。

## 2. 汇报结构

建议采用“需求范围 -> 流程与原型 -> 验收与分工 -> 下周行动”的叙事：

```text
项目定位
→ 本周增量
→ 完整必做范围
→ 师生平台流程与学生智能闭环
→ 权限和整体原型
→ 模块分工与验收证据
→ 个人需求/原型示例
→ 下周任务与风险
```

全稿分为四个部分：

1. 项目与本周目标。
2. 完整范围和整体原型。
3. 验收条件与个人成果。
4. 完成状态与下周计划。

## 4. 视觉与版式

- 画布：16:9。
- 背景：白色或极浅灰。
- 主文字：深海军蓝。
- 强调色：青绿色，用于流程、验收通过和负责人标识。
- 风险色：琥珀色，用于缺口、待核验和阻塞。
- 字体：微软雅黑；标题 28 至 32 磅，正文 18 至 22 磅。
- 每页最多 3 至 5 个核心要点。
- 平台流程和学生智能流程使用两条独立流程线，不混成一条。
- 所有“已完成”必须有负责人、证据入口和验收判据；没有证据统一标“未核验”。

## 5. 页面设计

### 第 1 页：封面

**标题：** 智能学习规划助手

**副标题：** 第 2 实践周需求确认汇报

**辅助信息：**

- 团队：A、B 两人
- 日期：2026-10-27
- 当前阶段：需求与原型确认

**版式：** 左侧项目名与副标题，右侧用“学生目标路径”和“教师班级任务”两个简洁节点表示双用户平台。

**讲述重点：** 本次汇报的重点是确认范围、原型、验收条件和分工，不把后续功能视为已完成。

**建议主讲与时间：** A，30 秒。

### 第 2 页：汇报安排与本次材料

**页面结论：** 本次汇报按教师要求提交四项可核查材料。

**关键内容：**

| 时间 | 内容 |
| --- | --- |
| 18 分钟 | 范围和方案讲解 |
| 6 分钟 | 平台流程和需求原型演示 |
| 4 分钟 | A、B 个人成果各 2 分钟 |
| 2 分钟 | 问题、范围确认与下周承诺 |

**四项材料：**

- 平台完成表。
- 本周原型或运行版本。
- 每人成果卡。
- 下周任务表。

**版式：** 上方 30 分钟时间轴，下方四张材料条目，每项注明证据入口。

**讲述重点：** 说明每个人都会展示，不用代码行数或学习时长代替成果。

**建议主讲与时间：** B，30 秒。

### 第 3 页：项目定位与两类用户

**页面结论：** 平台同时服务学生学习闭环和教师班级管理，而不是只做一个学习路径生成器。

**关键内容：**

- 学生：输入目标、完成诊断、接受路径、完成资源和任务、参加练习、查看反馈与进度。
- 教师：创建班级、发布资源与任务、查看提交、观察班级和学生进度。
- 智能能力：根据目标、诊断和证据生成并调整学习计划。

**版式：** 左侧学生任务，右侧教师任务，中间用共享的“班级资源、任务、学习记录”连接。

**讲述重点：** 明确核心用户不止学生，教师端是本期必须完成的基础平台能力。

**建议主讲与时间：** A，60 秒。

### 第 4 页：第 2 周增量与当前状态

**页面结论：** 本周完成的是需求确认材料，不是最终软件。

**状态矩阵：**

| 对象 | 本周状态 | 可展示证据 |
| --- | --- | --- |
| 完整功能清单 | 已形成文档 | SRS 功能主表 |
| 整体流程 | 已定义 | 师生平台流程、智能闭环 |
| 需求原型 | 待填入原型入口 | 页面流程图或交互原型 |
| 验收条件 | 已定义 | 功能对应的验收用例 |
| 代码与运行版本 | 未核验 | 不允许写“已完成” |

**版式：** 三列状态矩阵：已定义、原型待核验、未实现。不能虚构完成比例。

**讲述重点：** 诚实说明当前状态；第 2 周重点是确认“做什么、怎么证明”，不是展示最终系统。

**建议主讲与时间：** A，60 秒。

### 第 5 页：完整平台必做范围

**页面结论：** 最终平台的必做范围由基础平台能力和智能学习能力共同组成。

| 类别 | 必做功能 |
| --- | --- |
| 用户与角色 | 管理员、教师、学生；登录、会话和账号状态 |
| 班级与权限 | 建班、邀请码、班级成员、班级数据访问边界 |
| 课程资源 | 教师发布和下架、学生阅读、学习时长、历史引用 |
| 学习活动 | 教师任务、AI 任务、阅读、打卡与提交 |
| 练习反馈 | 客观题得分/答案/解析；主观题待复核；BKT 证据 |
| 记录与管理 | 学生个人进度、教师班级总览、风险和统计 |
| 智能能力 | 目标诊断、RAG/搜索、知识图谱、路径、BKT、重规划 |

**不做范围：**

- 不接教务系统。
- 不做跨学校多租户、家长端和学生社交。
- 不做代码沙箱自动判题。
- 不训练或微调生成模型。

**版式：** 上半部分为七类必做功能，下半部分用一条红色边界带列出非目标。

**讲述重点：** 现场请教师确认本期必做功能，不能自行删去已确认范围。

**建议主讲与时间：** A，90 秒。

### 第 6 页：教师平台端到端流程

**页面结论：** 基础平台链必须能完成“发布、学习、反馈、保存、查看”。

**流程：**

```text
教师登录
→ 查看本人班级
→ 发布资源或任务
→ 学生阅读、练习或提交
→ 系统生成并保存反馈
→ 学生查看进度
→ 教师查看班级与学生状态
```

**至少三个保存点：**

- 资源发布状态与授权范围。
- 学生提交或阅读记录。
- 教师可见的完成状态与统计。

**版式：** 横向主流程，下方单独标出三个数据库保存点和对应证据入口。

**讲述重点：** 平台不只是页面跳转，刷新或重启后学习记录仍能查询。

**建议主讲与时间：** B，90 秒。

### 第 7 页：学生智能学习闭环

**页面结论：** 智能能力要嵌入平台任务和记录，而不是独立展示一段模型回答。

**流程：**

```text
定目标
→ 诊断
→ 生成学习路径
→ 执行 AI 任务或教师任务
→ 练习反馈
→ BKT 更新
→ 保持或重规划
→ 学习记录与进度更新
```

**边界：**

- 教师任务计入学习负荷，但不直接修改 AI 路径。
- 阅读完成、任务完成和知识达标分别计算。
- 掌握度不足时生成补强和重规划建议，学生接受后才切换路径。

**版式：** 智能闭环放在上半区，教师任务从侧面进入执行与负荷层，不插入路径节点。

**讲述重点：** 强调智能能力最终要落到任务、反馈和记录，而不是停留在聊天框。

**建议主讲与时间：** A，90 秒。

### 第 8 页：角色、权限与资源可见性

**页面结论：** 每个用户只能看到完成本人任务所需的数据。

| 角色 | 可以访问 | 不可以访问 |
| --- | --- | --- |
| 学生 | 本人目标、路径、任务、练习、记录；已加入班级的资源和任务 | 同班其他学生详情、其他班数据 |
| 教师 | 本人负责班级、成员、资源、任务、提交和班级统计 | 无关班级、学生未关联本班的私人目标 |
| 管理员 | 学校账号、共享资料、图谱和模型配置 | 默认不阅读学生私人学习详情 |

**资源范围：**

- `school`：管理员共享资料。
- `class`：教师班级资料。
- `private`：学生私有上传。

**版式：** 左侧角色权限矩阵，右侧资源范围与“是否允许发送云端”的独立开关。

**讲述重点：** 权限检查要在服务端执行，前端隐藏按钮不能作为权限证明。

**建议主讲与时间：** B，90 秒。

### 第 9 页：整体产品原型与页面地图

**页面结论：** 第 2 周原型需要覆盖师生两条主链，而不是只画一个首页。

**学生页面：**

- 登录与加入班级。
- 目标和基础诊断。
- 学习路径与今日任务。
- 班级资源与阅读。
- 练习提交与反馈。
- 进度与重规划。

**教师页面：**

- 登录与班级管理。
- 班级进度总览。
- 资源发布与下架。
- 教师任务发布与撤回。
- 学生详情与提交查看。

**版式：** 使用两列页面地图，左侧学生、右侧教师；用共享班级数据连接。

**证据要求：** 每个页面放“原型入口”占位；没有原型时明确写“待补”，不能使用装饰性假截图。

**讲述重点：** 用一张图让教师确认范围是否完整，以及哪些页面属于必做。

**建议主讲与时间：** A，90 秒。

### 第 10 页：模块分工与接口边界

**页面结论：** 两名成员各自主责完整模块，同时共同维护跨模块契约。

| 负责人 | 主责模块 | 第 2 周应展示 |
| --- | --- | --- |
| A | 课程资源与知识底座、目标诊断、路径构建与审查、引用和搜索覆盖 | 资源发布/阅读原型，或目标诊断/首次路径原型 |
| B | 账号班级、教师任务、练习反馈、BKT、重规划与进度统计 | 教师任务/学生提交/教师进度原型 |
| 共同 | 数据契约、权限与全局预算、模块联调、周报和验收证据 | 一条跨角色流程与相关异常 |

**共享契约至少包括：**

- 用户、班级和成员关系。
- 资源授权与学习记录。
- 教师任务和学生分配。
- 练习提交、评分反馈和掌握证据。
- 路径版本、重规划事件和运行轨迹。

**版式：** 左右两列主责模块，中间一列共享契约。

**讲述重点：** 分工按业务模块而非前端/后端机械切开，每个人都要负责需求、设计、实现和测试。

**建议主讲与时间：** B，60 秒。

### 第 11 页：模块验收条件与证据链

**页面结论：** “做完”必须同时有功能结果、数据保存和可复查证据。

| 模块 | 最小验收条件 | 证据 |
| --- | --- | --- |
| 资源发布与阅读 | 有权限学生能看到资源，阅读分钟保存，重启后可查询 | 输入、操作、结果、记录 ID |
| 教师任务 | 指定学生收到任务，提交后教师看到完成状态 | 分配快照、提交记录、教师页面 |
| 练习反馈 | 客观题返回得分/答案/解析；重复提交不重复统计 | 作答、评分版本、反馈页面 |
| 学习目标与路径 | 目标可修正，路径通过先修与预算校验 | 路径版本、规则结果、引用 |
| BKT 与重规划 | 新证据生成掌握快照，低掌握触发补强建议 | 参数、旧值、新值、接受记录 |
| 权限与隐私 | 越权访问被拒绝并留下审计证据 | 角色矩阵、拒绝响应、日志 |

**版式：** 六行验收表，右侧预留“本周证据入口”。

**讲述重点：** 验收证据必须包含版本、输入、预期、实际、结论和执行人。

**建议主讲与时间：** A，60 秒。

### 第 12 页：平台完成表与本周缺口

**页面结论：** 用状态表区分文档已定义、原型已准备和仍未核验，不能把三者混为一谈。

| 模块 | 负责人 | 本周状态 | 证据入口 |
| --- | --- | --- | --- |
| 资源/阅读 | A | 需求已定义；原型待填 | 待填 |
| 目标/诊断/路径 | A | 需求已定义；原型待填 | 待填 |
| 账号/班级/权限 | B | 需求已定义；原型待填 | 待填 |
| 教师任务/反馈/进度 | B | 需求已定义；原型待填 | 待填 |
| BKT/重规划 | B | 需求已定义；原型待填 | 待填 |
| 全局预算/交接 | A/B | 需求已定义；证据待填 | 待填 |

**缺口格式：**

`具体缺口 -> 改进动作 -> 负责人 -> 完成时间 -> 复测判据`

**版式：** 主表加右侧缺口清单；未填证据的区域用琥珀色标记。

**讲述重点：** 提交前必须把“待填”替换为真实证据入口；如果确实没有，保留“未核验”。

**建议主讲与时间：** B，60 秒。

### 第 13 页：6 分钟原型演示路径

**页面结论：** 演示只覆盖一条师生交互链和一条学生智能链，避免 30 分钟被功能漫游占满。

**A 演示，约 3 分钟：**

1. 教师发布具有班级权限的资源。
2. 学生查看资源并记录阅读。
3. 刷新或重新进入后查询到记录。

**B 演示，约 3 分钟：**

1. 教师向指定学生发布任务。
2. 学生提交任务或完成客观练习。
3. 学生看到反馈。
4. 教师看到完成状态与班级进度变化。

**若原型尚未完成：**

- 演示可点击的需求原型。
- 明确标注“需求原型，不是运行版”。
- 讲清页面入口、数据保存点和预期验收结果。

**版式：** 左侧 A 三段演示，右侧 B 四段演示，中间显示证据入口与版本号。

**讲述重点：** 不打开无关页面，不用缓存或预制结果冒充运行结果。

**建议主讲与时间：** A/B，6 分钟。

### 第 14 页：A 个人成果卡

**页面结论：** A 的成果必须定位到具体需求、原型或流程，并说明验证边界。

| 字段 | 本周内容 |
| --- | --- |
| 我的任务 | 资源发布、阅读记录；目标诊断与首次路径设计 |
| 具体改动/产出 | 需求、验收条件和原型入口，待填真实链接 |
| 可打开成果 | 资源/阅读原型或目标/路径原型，待填 |
| 验证依据 | 输入、操作、预期、实际、版本与执行人 |
| 局限 | 未编码或未联调部分必须明确 |
| 下一步 | 第 3 周首条真实流程与接口契约 |

**版式：** 五段式成果卡，从上到下阅读；证据入口用明显链接或二维码。

**讲述重点：** 用“我做了什么、在哪里打开、怎样验证”回答个人贡献，不展示学习时长。

**建议主讲与时间：** A，2 分钟。

### 第 15 页：B 个人成果卡

**页面结论：** B 的成果必须覆盖班级任务、反馈或记录中的一条真实业务链。

| 字段 | 本周内容 |
| --- | --- |
| 我的任务 | 账号班级、教师任务、练习反馈和进度 |
