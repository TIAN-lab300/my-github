## 第 5 页：完整必做范围

### 必做范围由基础平台与智能能力共同构成

**核心表述：** 七类能力进入范围，四项非目标明确排除。

**基础平台与智能能力：**

| 类别 | 必做内容 |
| --- | --- |
| 用户与角色 | 管理员、教师、学生；登录与账号状态 |
| 班级与权限 | 建班、邀请码、成员、数据边界 |

## 第 6 页：教师平台流程

### 平台链必须从发布走到可查询的学习状态

**核心表述：** 页面跳转不算完成，刷新或重启后仍要能查到记录。

**主流程：**

```text
教师登录
→ 查看班级
→ 发布资源或任务
→ 学生阅读、练习或提交
→ 生成反馈并保存
→ 学生查看进度
→ 教师查看班级状态
```

**三个必须保存的节点：**

| 保存节点 | 内容 |
| --- | --- |
| 资源发布状态 | 授权范围与上下架状态 |
| 阅读与提交记录 | 学习分钟、练习与任务提交 |
| 教师可见状态与统计 | 完成状态、班级进度与查询结果 |

## 第 7 页：学生智能闭环

### 智能能力必须嵌入任务、反馈与记录

**核心表述：** 智能闭环最终要落到学习记录，而不是停留在聊天框。

**智能闭环：**

1. 定目标
2. 诊断
3. 生成路径
4. 执行任务
5. 练习反馈
6. BKT 更新
7. 保持或重规划
8. 记录与进度

**教师任务：**

- 侧向输入。
- 只计入学习负荷，不直接修改 AI 路径。

**三类结果分别计算：**

- 阅读完成。
- 任务完成。
- 知识达标。

**重规划规则：**

- 低掌握 → 补强建议 → 学生接受后才切换路径。

## 第 8 页：角色与权限

### 每个角色只看到完成本人任务所需的数据

**核心表述：** 权限由服务端执行；资源范围与云端发送开关分别控制。

| 角色 | 可以访问 | 不可以访问 |
| --- | --- | --- |
| 学生 | 本人目标、路径、任务、练习、记录；已加入班级的资源和任务 | 同班其他学生详情、其他班数据 |
| 教师 | 本人负责班级、成员、资源、任务、提交和班级统计 | 无关班级、学生未关联本班的私人目标 |
| 管理员 | 学校账号、共享资料、图谱和模型配置 | 默认不阅读学生私人学习详情 |

**资源范围：**

| 范围 | 含义 |
| --- | --- |
| `school` | 管理员共享资料 |
| `class` | 教师班级资料 |
| `private` | 学生私有上传 |

**云端发送：**

- 是否允许发送云端，独立控制。
- 前端隐藏不能作为权限证明。

## 第 11 页：验收与证据

### “做完”必须同时有功能结果、保存记录和可复查证据

**证据链：** 版本 → 输入 → 预期 → 实际 → 结论 → 执行人。

| 模块 | 最小验收条件 | 证据 |
| --- | --- | --- |
| 资源发布与阅读 | 有权限可见；阅读分钟保存；重启后可查询 | 输入、操作、结果、记录 ID |
| 教师任务 | 指定学生收到任务；提交后教师看到完成状态 | 分配快照、提交记录、教师页面 |
| 练习反馈 | 客观题返回得分、答案、解析；重复提交不重复统计 | 作答、评分版本、反馈页面 |
| 学习目标与路径 | 目标可修正；路径通过先修与预算校验 | 路径版本、规则结果、引用 |
| BKT 与重规划 | 新证据生成掌握快照；低掌握触发补强建议 | 参数、旧值、新值、接受记录 |
| 权限与隐私 | 越权访问被拒绝并留下审计证据 | 角色矩阵、拒绝响应、日志 |

## 第 13 页：6 分钟演示

### 6 分钟演示只跑两条关键链

**核心表述：** 一人 3 分钟，只展示能落证据的师生交互与学生智能链。

**A：资源到阅读记录，约 3 分钟**

1. 教师发布班级资源，记录发布状态与授权范围。
2. 学生查看并记录阅读，确认阅读分钟被保存。
3. 刷新或重新进入，仍能查询到阅读记录。

**B：任务到教师进度，约 3 分钟**

1. 向指定学生发布任务。
2. 学生提交或完成练习。
3. 学生看到反馈。
4. 教师看到完成状态与班级进度。

**证据要求：**

- 进度必须由提交记录驱动。
- 证据入口待补。
- 版本待填。
- 需求原型，不是运行版。
- 不打开无关页面。

## 第 16 页：第 3 周承诺

### 第 3 周从需求原型推进到首条真实运行链

**核心表述：** 先统一账号、数据契约与权限，再验证两条业务链。

**下周任务与验收判据：**

| 任务 | 负责人 | 验收判据 |
| --- | --- | --- |
| 资源发布 → 阅读 → 记录 | A | 新账号只看到有权资源，记录重启后可查 |
| 目标诊断 → 首次路径 | A | 路径通过先修与预算规则，证据可追踪 |
| 账号班级 → 任务提交 → 教师进度 | B | 指定学生收到任务，提交后进度更新 |
| 练习反馈 → BKT 快照 | B | 评分和解析保存，重复提交不重复更新 |
| 统一数据契约与权限 | A/B | 关键字段、错误码与越权拒绝规则冻结 |
| 云端模型和搜索试验 | A/B | 真实密钥、结构化返回和失败状态有记录 |

**主要风险：**

- 两人范围过大。
- 只有文档没有原型。
- API Key、配额或联网搜索不可用。
- 权限、班级归属和全局预算遗漏。
- 只验证页面，没有保存和查询证据。

**课堂确认项：**

- 必做模块与需求原型边界。
- 单机或局域网。
- 首条真实流程。

**结束表述：**

> 第 2 周确认范围和验收方式；第 3 周开始，每条模块必须提供可运行或可核查的原型证据。
