本计划把修改后的六份 Markdown 文档转化为可分配、可集成、可验收的开发任务。实施结果须同时具备学生学习闭环、教师教学管理闭环及管理员账号和配置管理能力，不能只完成 AI 路径演示。

## 2. 启动假设与排期规则

1. 当前按第 2 周汇报结束、进入实现阶段安排；第 3～8 周的日历日期由实际课程表换算，不以文件日期推断。
2. A/B 为角色占位，启动时替换为真实姓名。每人承担自己模块的后端、前端、测试和说明，不按“一个人只写前端、一个人只写后端”分割。
3. 本计划默认单机多账号演示、Windows 11、模块化单体。局域网多终端属于需要明确部署边界的变更。
4. 工时为建议预算，每人每周约 20 小时，其中功能开发约 14 小时，联调与验证约 4 小时，证据与汇报约 2 小时。实际投入不足时立即调整展示复杂度和任务拆分；此预算不构成按期完成保证。
5. 各周 Wn-D1～D5 表示该实践周的五个工作日；周交付截止为该周汇报前 24 小时。若两者冲突，以更早者为准。启动时在任务系统填入实际日期。
6. 所有现有模块初始记为“待核验”。通过代码、运行和证据核查后再调整状态，避免重复开发，也不能凭文档跳过验证。

## 3. 实施范围与三端交付

| 端 | 必须提供的可操作能力 | 首次可用 / 完整接入 |
| --- | --- | --- |
| 学生端 | 登录入班、资源阅读与记录、教师任务提交、题目反馈、目标与诊断、学习路径、打卡、BKT 变化、重规划接受/拒绝、本人学生画像与历史 | 第 3 周基础链 / 第 5 周全部 |
| 教师端 | 本人班级及邀请码、资源发布/下架、任务发布/撤回、提交与主观题复核、班级画像、本班学生画像授权投影 | 第 3 周基础链 / 第 5 周全部 |
| 管理员端 | 账号创建/停用/重置、云端模型配置评估与激活、必要审计和运维入口 | 第 3 周账号 / 第 5 周全部 |

资源发布是教学前台业务，不能用管理员后台向量导入替代；页面隐藏不是服务端授权。管理员模型配置界面可以简洁，但配置版本、评估后激活和密钥保护必须实现。初始化、备份、恢复可通过受控 CLI 完成并提供使用说明。

### 3.1 两条最终业务链

**教学平台链：** 管理员创建账号 → 教师建班和发布资源/任务 → 学生入班、阅读、作答/提交 → 获得反馈 → 保存记录 → 画像刷新 → 学生查本人画像、教师查本班班级画像与授权投影。

**智能学习链：** 学生设置目标 → 构建候选知识框架和覆盖检查 → 必要时补充真实联网证据 → 诊断 → 图约束规划与校验 → 接受路径并学习 → 测验形成证据 → BKT 更新 → 重规划预览 → 接受或拒绝。

教师任务进入同一学生的全局时间预算，冲突时产生重规划建议，不能直接改写 AI 路径。阅读完成、任务完成、知识掌握分别记录。

## 8. 必须先确定的数据与接口契约

### 8.1 第 3 周冻结的共享契约

- 身份上下文：用户 ID、角色、学校、班级归属；服务端取身份，不信任前端自报 owner。
- 资源：scope、class_id、不可变文档版本、发布状态、cloud_allowed。
- 学习事件：来源类型、来源 ID、实际分钟、业务事件唯一标识，阅读与任务事件不得重复计时。
- 任务与提交：发布分配快照、截止时间、提交版本、评分状态；发布后不原地修改题目答案。
- 全局预算：学生时区、日/周上限、预约与实际消耗、budget_version；所有活动目标和班级任务共享。
- 长任务：run_id、状态、阶段、错误、取消/重试；首次返回 202 不代表生成成功。
- 追踪字段：request_id、业务版本、执行人、时间；真实密钥、密码及不必要个人信息不得进入日志。
- 画像：scope_type、class_id、统计窗口、source_watermark、payload、data_quality、version；学生本人完整画像和教师班级授权投影分开。

### 8.2 第 4 周冻结的智能契约

GoalSpec 使用 target_skill_ids 数组；规划输入引用目标、掌握度、预算版本。候选图谱先在候选区补齐节点、题目和证据，再执行诊断和正式规划。路径绑定图谱快照、规则校验记录和来源版本。

分别使用内容状态 draft/verified、路径状态 pending_acceptance/active/superseded/rejected、校验结果 validation.is_valid，不用一个 valid 字段混代。draft 不能发布正式路径。

### 8.3 事务、去重与恢复要求

| 写入场景 | 必须保持的原子性或补偿措施 | 验证 |
| --- | --- | --- |
| 作答评分 | 作答、证据、BKT 去重、快照和待处理事件在短事务内提交 | 同 attempt 换幂等键仍仅应用一次；模型失败不撤销作答 |
| 接受路径/重规划 | 再查目标/掌握度/预算/预约版本，切换活动路径并更新本目标预约 | 旧预览返回 409；不能覆盖其他目标预约 |
| 教师发布/撤回 | 分配、预约和审计同步提交 | 撤回释放负荷；晚入班不自动获得旧分配 |
| 资源索引 | Chroma staging 完成后切换 SQL 发布指针；失败清理/重建 | 中断后不出现已发布但索引缺失，不能声称跨库自动回滚 |
| Agent 中断 | 保存检查点及持久事件，按事件 ID 幂等恢复 | 重试不重复评分、不重复发布、不重复 BKT |
| 画像刷新 | 领域事件、刷新任务、快照版本和水位在同一短事务提交；旧快照只读 | 同水位不重复生成；失败保留旧版本并标 stale |

主观题 pending_review 不更新 BKT；教师有效评分后形成证据；更正评分重放观察序列，不能再追加一次掌握增益。补强创建新 task，不能重复插入相同路径知识节点。

### 8.4 画像契约与刷新事务

学生画像使用 `StudentProfileSnapshot`：

```text
id, student_id, scope_type, class_id?, version,
stats_window_start, stats_window_end,
source_watermark_json, payload_json, data_quality_json, generated_at
```

班级画像使用 `ClassProfileSnapshot`：

```text
id, class_id, owner_teacher_id, version,
stats_window_start, stats_window_end,
source_watermark_json, payload_json, data_quality_json, generated_at
```

学生画像载荷至少包含 `learning_context`、`learning_behavior`、`mastery_state`、`evidence_quality`、`risk_summary` 和 `data_quality`。班级画像载荷至少包含 `class_scope`、`participation`、`task_metrics`、`learning_time`、`mastery_distribution`、`common_weak_nodes`、`risk_students` 和 `data_quality`。

刷新规则：

- 诊断、打卡、教师任务提交、资源学习、评分、BKT 更新、目标班级关联、成员变化写入领域事件。
- `profile_refresh_events` 按 `source_event_id` 幂等消费，并比较 `source_watermark_json`。
- 水位相同不生成新版本；水位变化生成不可变新版本。
- 刷新失败保留上一有效快照并标记 `stale`，接口不得返回伪造新版本。
- 学生画像查询可返回本人完整画像；教师画像查询只使用本班授权投影。
- 数值、比率、风险原因和空值口径由 SQL/Python 确定性计算，LLM 只能解释。

画像接口：

- `GET /learners/me/profile`
- `GET /learners/me/profile/history`
- `GET /teacher/classes/{class_id}/profile`
- `GET /teacher/classes/{class_id}/profile/history`
- `GET /teacher/classes/{class_id}/students/{student_id}/profile`

画像 GET 在水位变化时可以生成新的不可变快照并返回；不得修改原始学习事实，刷新失败必须返回旧版本及 `stale` 状态。

班级画像口径：

- 任务完成率分母为已发布且未撤回任务的有效分配，包含逾期未交；无条件时显示“暂无任务”。
- 按时率分母为已完成分配；逾期补交算完成但不按时。
- 逾期人数按学生去重；已补交学生不再算当前逾期。
- 实际学习时长来自非重复授权学习事件，不使用计划时长。
- 掌握度分布只使用本班有效证据形成的快照；无证据显示未知，不推断薄弱。

## 9. AI 能力实施顺序与退出条件

1. **能力探测（W3）：** 使用实际账号验证目标端点的生成、搜索、来源返回、结构化输出与超时行为。搜索取证和结构化生成分步；不将应用过滤参数直接当作供应商参数。记录真实模型/配置、响应及能力缺口。
2. **确定性基础（W4）：** 完成图的环检查、先修闭包、预算可行性、引用授权、BKT 计算，再让 Agent 调用这些服务。LLM 不能自行决定绕过规则。
3. **四 Agent 编排（W4）：** GoalDiagnosisAgent → PathBuildingAgent → PlanReviewAgent，学习证据触发 LearningReplanAgent。每步记录输入版本、输出、工具与错误；审查必须调用真实校验器。
4. **新主题与时效（W5）：** 本地完整且非时效查询不联网；缺失或时效要求触发搜索；仅上传模式缺证据立即进入 draft，不死循环。最多两轮搜索，搜索后重新检查覆盖。
5. **失败与恢复（W5）：** JSON 修复最多两次、路径修复最多三次，全部服从总时限 180 秒；取消保留已提交学习事实，未接受候选不生效。
6. **评价（W6）：** 固定 60 例：20 已覆盖目标、20 缺失/新主题、20 时效/异常。冻结输入与期望后运行，分别报告首次和有限修复后的表现。
7. **画像解释（W4 首版/W5 完整）：** 学生画像和班级画像先由确定性聚合生成，LLM 仅基于快照事实生成解释；过期快照必须先刷新或明确标注，不能让模型补造指标。

模型不可用时本地登录、历史、资源浏览继续工作；AI 显示明确失败，不制造“实时”内容。正式验收需要真实云端调用和本次搜索，测试替身只用于可重复自动测试且必须标明。

## 10. 测试、质量门槛与证据

### 10.1 验证层次

| 层次 | 重点 | 主责 | 执行时机 |
| --- | --- | --- | --- |
| 单元/规则测试 | BKT 手算、图环与先修、预算边界、统计分母、状态迁移 | 各模块作者 | 模块提交前 |
| 画像/规则测试 | 学生/班级聚合、指标分母、水位、过期判断、历史版本和隐私投影 | B；A 复核解释 | 每次画像服务变更 |
| API/数据库集成 | 三角色/对象授权、唯一约束、幂等、迁移、事务与版本冲突 | B；A 复核资源/RAG | 每次集成 |
| 跨模块端到端 | AT-023 基础平台链、AT-015 智能链、AT-022 师生链、AT-031～033 画像链 | A/B 轮换操作 | W3 起；W4 起覆盖智能链和画像 |
| 故障与恢复 | 网络断开、错误 Key、非法 JSON、取消、进程中断、索引失败 | B 主持，A 处理云端/索引 | W5 起，W6 集中 |
| 智能/性能评价 | 60 例固定集、来源与时效、P50/P95、失败率和用量 | A | W6，相关修复后复测 |
| 部署与交接 | 他人安装、初始化、备份恢复、三轮现场演练 | B 主持，A 配合 | W7 |

必须包含的回归样例：BKT p=0.62 错误作答，learn=0.2、slip=0.1、guess=0.25，结果约 0.342939；重复同证据不得再次更新；两目标加两班任务共享预算；4个班级任务分配中2完成、1未逾期未交、1逾期未交时完成率50%、按时率50%、逾期人数1；同水位画像不重复生成；教师不能读学生私人目标、跨班引用、画像投影或轨迹；未作答不能被误记为 0 分掌握度。

### 10.2 发布门槛

- 任一正式发布路径的 VR-001～008 必须全部通过，硬先修冲突为 0；正式节点引用覆盖率及引用存在率必须 100%。
- 可行目标规划成功率目标至少 95%；首次 Schema 合法率目标至少 95%；20 个新主题至少 16 个通过。失败和超时留在分母，不能用这些比例放宽正式路径规则。
- 时效声明发布合规率必须 100%；没有时效声明写 N/A；来源可访问率目标至少 95%，未核实不能记成功。
- 性能按技术设计 20.5 的固定机器/数据/并发口径执行，至少 30 次，报告 P50/P95 与失败率；180 秒为端到端总预算，不能每层重新计时。
- 阻断性问题包括越权泄漏、数据损坏、无效路径发布、核心链无法运行、重复 BKT。验收版本不得遗留此类已知缺陷。一般展示缺陷须列限制和计划。
- 学生/班级画像必须可由固定输入确定性复算；班级画像不得包含私人目标或其他班证据；旧快照不得冒充最新。

### 10.3 证据记录格式

每个 AT 建议保存一条记录：`AT编号 / FR编号 / commit或版本 / 环境与模型配置 / 前置数据 / 输入与操作 / 预期 / 实际 / 通过、失败或未测试 / 执行人 / 时间 / 截图或日志位置 / 缺陷及复测记录`。

截图只能辅助证明结果，需结合真实接口、记录 ID、run_id 或数据库查询。不得把“步骤已写好”记为“测试通过”。首次新请求与同键重放分别验证；run_id 本身不能证明未复用缓存结果。

## 11. 双人协作与变更管理

每日用 10 分钟对齐已合入成果、阻塞、下一交付。共享接口变更当天通知并同步 Schema、前端类型、迁移、测试和文档。每个任务切成可在一至两天内集成的增量，分支不长期隔离。

建议使用主分支加短期功能分支；合并前由另一人复核关键权限、预算和状态变更。数据库迁移由 B 统一编号，A 提供资源/图谱表变更，禁止两人直接改共享数据库绕过迁移。

完成定义：代码已进入集成版本，页面可操作，数据可持久化，权限与错误分支已验证，相关测试通过，证据可定位，文档已同步。只完成后端、只有截图、尚未联调均标“部分完成”。

新增需求须记录用途、影响 FR/AT、工时、依赖和替代方案。优先减少装饰、非核心筛选、复杂候选展示、轨迹美化；不擅自删除三角色、真实 RAG/搜索、先修与预算、BKT/重规划、权限及持久化。若核心范围确实无法按期完成，向课堂负责人提出具体调整，保留待确认状态。
