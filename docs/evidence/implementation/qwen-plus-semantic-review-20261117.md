## 优先修订的问题

1. `functions-07`：两组样本不能唯一确定任意函数。`f(x)=2x+1`和`g(x)=2x+1+(x-1)(x-2)`都满足f(1)=3、f(2)=5，但在x=3时不同。应限定仿射函数族，或改为列举多个相容函数。
2. `functions-03`、`stack-07`、`stack-20`：把输入中没有的实例或图示当成既有材料，要求摘录、结合或给出处。应真实提供素材，或明确为新编/自绘示例，不能伪称来自原文。
3. `stack-02`、`stack-08`、`stack-10`、`stack-11`、`stack-12`、`stack-14`、`stack-20`：逐次调用返回的完整性与固定快照数量/选取范围不匹配。应先给具体代码，再由调用事件导出快照数；抽样与全程必须区分。
4. `stack-12`：未定义函数签名却要求f(1)、f(2,3)、f()都有可预测返回值；普通固定参数函数可能触发TypeError，须给签名/默认值/变参规则。

## 45份候选的共同适用限制

- 输出多为“给定函数/代码/若干题”式活动安排，输入仅给出原则性短文，未绑定具体资源版本、可领取题目、标准答案或评分标尺。作为计划草案可以讨论，但不能宣称可直接下发执行；这也是评价场景与契约的缺口，不能全部归咎于模型。
- 引用原文字串正确不等于足以支撑阶乘、斐波那契、返回地址、局部变量位置、默认参数等新要求。新编示例可以使用，但应明示身份并核验，而非当作已有证据。
- 15份有材料且目标已掌握的场景仍反复安排基础活动。原提示词强制practice+assessment，与“达标后跳过/明确复习”策略有冲突，应修订评价契约再判断模型，不能直接记为模型违反指令。
- 15份候选先修未知时虽把diagnose放首位，但未说明检测通过/未通过后的分支。真实执行必须由服务端门控，不能按固定时间过后默认先修达标。
- 45份候选全部用满预算，同类简单任务随预算增大而显著加时。预算应是上限；时长合理性需基于真实题目与试测，不能只检查未超预算。
- 没有编造视频是正面结果；偏好视频却仅有文本时，应解释回退原因，而不是假称满足视频偏好。
