## 4. B1编码前详细设计

### 4.1 初始化与资料

复用cli初始化入口，数据库用户名唯一；重复初始化不覆盖密码、角色或真实数据。初始密码仅写现有受忽略文件，页面及日志不展示。资料编辑采用允许字段清单，仅姓名等允许属性可改，角色、状态、auth_version不可通过资料接口改变。前端成功后同步当前身份展示；失败保留输入。

验收ACCOUNT-01：空库初始化成功、重复执行无覆盖、迁移后再初始化无重复。ACCOUNT-04：合法姓名保存刷新仍在，空值/超长拒绝，附带role字段不能提权，其他人资料不能修改。

### 4.2 班级生命周期

继续使用classes、memberships、invites、assignments、reservations。编辑必须携带version；陈旧版本409且不发生部分写入。归档后禁止新邀请、入班、任务发布及新分配；历史成绩保留。拟补齐归档时取消未完成分配及其未来教师预约，已完成学习事实不删除；此行为需与既定任务撤回规则统一，归档提示列出受影响数量。

归档联动在同一事务完成：检查所有权/version→更新班级→撤销邀请→处理未完成分配及预约→写画像刷新事件→审计。失败整体回滚。恢复班级不自动复活旧邀请码或已取消任务。

晚入班按需求SF-CLASS-09新建关联补发任务，不追加原任务分配。POST /api/v1/teacher/tasks/{id}/supplement接收student_ids和expected_version，校验教师所有权、有效班级、有效成员及原任务状态，复制冻结内容为指定接收人的新草稿，通过task_reissues关联原任务。相同接收人的未发布关联草稿复用，防止重复点击。教师核对截止时间后显式发布；原分配、成绩和历史不变。发布沿用既有负荷冲突提示，不在创建草稿时预约预算。

CLASS-01～09逐项至少覆盖：编辑冲突、他人班级越权、邀请码过期/撤销/次数耗尽、重复加入不扣次数、成员名单隔离、退班后失权及释放预约、归档禁止写入、补发重复不新增。邀请原码仅生成时展示，审计不保存原码。

### 4.3 资源01～09

复用resource_versions不可变历史，不原地覆盖已被引用的正文。列表筛选先应用权限再分页；结果不暴露私人标题或数量。上传按文件分别报告成功/失败，文件扩展名、内容类型、可解析内容及大小共同校验，不能把改扩展名当作格式转换。

解析改为持久任务：queued→running→ready/failed；应用重启将失去租约的running恢复待处理。ready要求正文和必要索引均可用；附件保存成功不等于正文可检索。重试绑定同一资源版本，并设置最大尝试次数和错误原因；版本已替换时旧任务不得切换当前指针。

拟新增parse_jobs(id,resource_version_id,status,attempts,lease_until,error_code,created_at,updated_at)，同一版本同时最多一个有效任务。迁移接在当前0004之后，实际编号以编码时迁移头为准。已有就绪版本保持就绪，不批量重新解析；新版本失败保留旧引用。长期解析移出数据库写事务。

现有上传客户端与异步响应须同批更新。新上传返回每文件resource_id、version_id、job_id、status；轮询拟新增GET /api/v1/resources/{id}/parse-jobs/{job_id}，只向资源所有者开放任务细节。现有retry-parse入口复用队列，重复点击复用活动任务。发布仍由服务端检查版本就绪、来源许可和班级有效状态。

前端显示上传/解析/失败/发布状态，失败提供可操作说明；切换页面终止轮询，重新打开恢复查询。下载和预览每次授权，路径不得来自客户端任意文件名。音视频与字幕绑定具体版本，字幕失败不伪造正文。RESOURCE-09的具体播放器行为以v3.3对应条目复核后实现，不因批次拆分漏掉后续字幕等功能。

验收重点：伪装文件拒绝、部分上传失败可重试、旧version提交409、解析故障后恢复、下架后学生不能下载、更新后旧路径引用仍可追溯且不绕过当前权限。

## 5. 后续模块技术设计

### 5.1 教学、评分与事实

任务发布原子冻结题目、接收人和资源版本；修订创建新草稿并关联旧任务，不改历史成绩。提交采用幂等键，响应丢失重试返回既有结果。主观题进入待复核，教师按rubric评分并留更正原因；更正通过有效证据重放掌握度，不能追加同一证据两次。阅读、打卡只记活动，不能直接标记掌握。

统一写事务：作答/复核→有效评分证据→掌握度与水位→刷新事件。前端只显示服务端成绩；提交前不下发答案。任务资源下架、成员退出、截止到达及重复提交需有独立验收。

### 5.2 目标、诊断与预算

新主题先保存结构化草案，经用户修正和证据覆盖检查后进入可诊断状态。知识点需有题目与资源版本映射，题库不足返回明确缺口。现有固定六题及等价重测作为固定主题基线，不标为通用生成题库。

预算以学生为聚合边界，包含所有目标与教师任务，使用用户时区确定学习日，存储UTC。时间设置改变只生成影响说明和调整候选，不直接覆盖已接受路径。诊断草稿不评分；提交校验完整、选项合法、快照一致，重复提交返回既有结果。

### 5.3 规划与重规划

保留现有planning服务的规则校验，将候选生成与确定性裁决拆开。模型只提议节点、资源和解释，服务端验证先修无环、证据覆盖、时长、全局预算以及VR-001～008。任一硬约束失败不形成正式路径。

运行输入指纹包含目标、图谱、资源、掌握度、预算和模型配置版本。接受预览在事务内重新核对指纹和版本，释放被替换的未来预约并写新预约；另一目标并发接受导致版本变化时409，不能超卖时间。拒绝保留原路径和风险提示。区分“已证明不可行”与“搜索未找到”，不可将有限搜索失败当数学不可行。

### 5.4 检索、模型与来源

FTS5保留为关键词召回；新增向量索引适配器，索引键使用资源版本和片段ID。分块保留页码/字幕时间定位。混合召回先限定授权候选，结果回查SQL状态后融合去重，Chroma仅为可重建索引。待编码前验证本地依赖兼容性并锁定版本，本文件不声称已验证新依赖。

联网仅在用户允许且覆盖不足时触发；网址登记不等于来源已验证。抓取限定http/https，拒绝本机、私网及重定向到受限地址，限制大小、超时和次数；记录获取时间、正文摘要、哈希及知识点支持关系。无法读取正文的URL标为未核实，不能作为硬证据。撤回云端授权后不得继续发送相应私有正文。

网关统一结构化输出校验、脱敏错误、用量和超时。模型配置先能力试验再评估激活，密钥只由环境加载，不进入前端、审计或报告。四Agent分别拥有诊断、候选构造、规则审查和解释/持久化交接职责；继续保留确定性规则，不能仅把本地函数换名就宣称云端智能完成。

拟增加source_snapshots、index_jobs和model_evaluations等持久记录；字段至少包含输入/配置版本、状态、引用、错误、耗时及时间。先检查现有迁移是否已有等价实体，再增量迁移，禁止建立重复事实表。解析和索引之间用持久事件衔接，不宣称SQLite与向量库拥有分布式事务。

### 5.5 画像和运行恢复

沿用已实现profile_refresh_events与后台消费者，补多次失败、重启、重复消费及班级刷新隔离。失败展示旧快照和更新时间，不能呈现为最新；统计值从事实聚合，模型解释不得改写数值。教师只得到关联班级授权投影，不能获得学生其他私人目标和班外数据。

## 6. 错误、兼容与实施组织

统一401身份失效、403权限不足、409版本/状态冲突、422输入错误、429限流、503依赖不可用；响应包含可读message和request_id。已有不同错误码先核对客户端兼容性，不在单个模块随意改变公共协议。

保留api现有路由；复杂规则逐步移到services，main.tsx按模块提取页面组件，先保持视觉和导航。每批同时提交接口、页面、迁移和证据；不做与功能无关的全量重构。

迁移前一致性备份数据库及附件，记录版本和校验。旧库升级在副本测试；涉及新状态的降级优先恢复经验证的备份到独立目录，不直接删除生产表。运行服务仍使用现有本地8000入口。

## 7. 测试与准入条件

每项SF登记：需求编号→设计规则→源码入口→输入→预期→实际→证据→结论。正常和关键异常缺一不可；页面交互由浏览器验收，接口测试不能代替密码显隐、确认弹窗或状态提示等交互验收。

必须保留跨角色、跨班级、跨学生越权测试，以及并发提交、陈旧版本、重启持久化、外部失败和事务回滚。测试使用独立临时数据，不能污染真实学生记录。

AI评价沿用技术设计20.5：冻结至少60例（固定目标、新主题、时效/异常各20），单例最多2轮搜索、2次JSON修复、3次路径修复，整体180秒内。首次JSON合法率≥95%，可行输入规划成功率≥95%，新主题至少16/20通过；失败和超时计入分母。发布路径规则通过率必须100%，硬先修冲突0。记录修复前后、耗时、来源和供应商可用的用量数据，不以“接口返回成功”替代质量评价。

每批通过适用后端测试、前端构建、关键浏览器流程后才能更新台账。证据写入docs/evidence/implementation，注明版本及环境；全量报告不能覆盖掉失败复测历史。

### 11.1 公共执行与验证契约

所有接口使用/api/v1前缀。既有物理表classes、resource_versions、attempts、profile_refresh_events优先复用，模块逻辑表名在迁移设计时映射，禁止重复建设同一事实。既有接口以app/api路由为兼容基线，新增字段默认兼容旧数据，公开DTO隐藏密码哈希、令牌、storage_key和密钥环境值。

写入流程为校验输入、认证、对象授权、读取版本、执行业务事务、追加审计/刷新事件、返回公开结果。长任务202并返回run/job ID，查询接口读取持久状态。401清私密视图，403/404阻止访问，409提示刷新，422定位输入，429附可重试时间，503说明依赖故障。失败事务不留部分业务写入。

## 4. 架构设计与技术决策

采用 React + TypeScript + Vite、FastAPI、SQLAlchemy/Alembic、SQLite/FTS5、Chroma、LangGraph 和服务端千问网关，延续既有技术基线。这里不指定未经环境验证的依赖版本；编码启动时验证 Windows 安装和真实能力并锁定依赖。

浏览器通过同源 `/api/v1` 访问后端，开发期由前端代理转发。后端按认证、班级、资源、任务、评测、规划、画像拆分模块，统一进程部署。SQLite 保存业务事实；文件目录保存附件；FTS5/Chroma 是可重建检索索引，不是业务真相来源。

请求依次经过身份校验、输入 Schema、对象授权、业务服务、事务和返回 DTO。接口层不直接调用模型或自行聚合画像；Agent 调用服务，不绕过权限和事务直接写表。

生成和解析采用持久运行记录，POST 返回202及 run_id，GET只查询。单机后台执行器处理任务；运行恢复以持久状态与幂等事件为依据，不能依赖进程内列表。第三周优先落实教学链，第四周接入完整运行轨迹与检查点。

文件上传不在长数据库事务中执行。先保存临时文件、校验并创建资源版本，解析和索引完成后原子切换 SQL 索引指针。Chroma 与 SQLite 不构成跨库事务；失败保留明确状态，允许幂等重建。

## 7. 状态、事务和核心算法

资源分别维护发布状态draft/published/withdrawn、解析状态pending/processing/ready/failed和索引状态；附件可播放或下载不代表正文可参与RAG。下架后停止新的学生读取和检索，保留已有作答所需来源快照。

任务draft → published → withdrawn/closed。发布时冻结题目与分配名单；晚入班学生不自动获得旧分配。作答submitted → scored或pending_review → scored。主观题待复核不更新BKT。

路径pending_acceptance → active → superseded，候选可rejected；内容draft/verified独立于路径状态。接受必须重新比较目标、掌握度、预算、预约版本；不一致返回409。

评分事务：校验分配与题目版本 → 保存答案 → 客观规则评分 → 写证据 → 更新BKT → 写学习事件与待刷新事件 → 提交。相同作答ID重复请求返回原结果，即使换幂等键也不重复增加掌握度。模型解释失败不回滚成绩。

BKT使用既有参数契约。先按正确/错误观察计算后验，再计算学习转移：P(next)=P(posterior)+(1-P(posterior))*P(T)。参数P(L0)、P(T)、P(G)、P(S)版本化；评分更正重放观察序列，不能追加一次增益。

规划：授权资源检索 → 候选知识图与题目覆盖检查 → 缺口补齐 → 诊断 → 按先修拓扑排序 → 结合掌握度筛选 → 在全局剩余预算中排期 → 校验来源、先修、重复、负荷 → 保存待接受路径。图有环、来源不足、预算不足分别给出明确错误或草稿状态。

重规划：基于当前路径和输入版本创建预览；拒绝只记录选择；接受在短事务内重新验证版本、替换本目标预约并切换活动路径。画像消费事件生成不可变快照，同水位不重复生成，刷新失败保留旧快照并标stale。

## 11. 安全、失败恢复与设计验证

文件使用服务端随机路径，不接受客户端指定保存路径；限制扩展名、内容类型与大小，不执行上传内容；下载经授权。外链正文抓取必须限制协议、阻止私有/回环目标并校验重定向，避免把登记链接直接交给无约束抓取器。网页和文件内容只作为资料，不能作为系统指令。

密码采用成熟哈希库，会话和邀请码仅存哈希；密钥保存在服务端环境配置或受控秘密存储，不进Git和日志。SQLite短事务，长模型请求不持有写锁；忙碌或超时给出可重试错误。

| 验证场景 | 设计预期 |
| --- | --- |
| 两教师两班交叉读取 | 服务端拒绝；学生端不泄露对象存在性 |
| 提交后重启、重复发送作答 | 结果持久化且不重复评分/BKT |
| 上传成功但解析失败 | 可见失败原因；不伪装可检索正文 |
| 元数据命中但正文缺失 | 不宣称知识覆盖充分 |
| 未达标测验后重规划、拒绝与旧版本接受 | 有掌握度依据；拒绝保留原路径；旧版本409 |
| 模型超时或JSON非法 | 运行明确失败或有限重试，无伪造正式路径 |
| 无学习数据或画像刷新失败 | 显示无数据/旧快照过期，不编造新数值 |
| 账号停用或密码重置 | 旧会话立即失效 |

编码前设计检查：原型页面都有模块映射；实体关系和唯一约束明确；基础链每一步有接口及事务归属；权限检查贯穿资源下载和检索；模型输出不能绕过规则；运行失败与版本冲突有页面反馈。检查完成不等于运行测试通过。
