## 1. 文档说明

### 1.1 文档目的

本文档将《智能学习规划助手项目设计方案》v3.2 转化为可实现、可追踪、可测试和可验收的需求规格。本文档规定学生 AI 学习闭环、学生画像、教师班级画像、教师端、平台权限、知识覆盖门控、联网搜索规则、数据要求、非功能指标和现场验收条件。

本文档是课程项目开发、测试、现场演示和答辩验收的共同需求基线。实现不得通过预生成路径、缓存规划响应或直接修改数据库来跳过现场闭环中的核心步骤。

### 1.2 文档适用范围

本文档覆盖第8实践周前交付的课程项目MVP，包括：

- 学生端学习目标和学习者画像管理。
- 基础诊断、知识缺口计算和个性化路径生成。
- 学习任务、打卡、测验证据和 BKT 掌握度更新。
- 路径重规划和原路径差异展示。
- RAG、知识图谱、约束规划、规则校验和 Agent 轨迹。
- 千问云端模型调用、原生联网搜索、Web 证据保存和来源校验。
- 单次现场连续演示六阶段闭环。
- 管理员、教师和学生账号登录及角色权限。
- 多教师、多班级、邀请码加入和班级成员管理。
- 教师班级总览、学生详情、教师任务和提交查看。
- 学生画像快照、教师班级画像快照和画像刷新历史。

后续演进功能不属于当前版本必须交付范围。

| 术语 | 定义 |

| Student Profile Snapshot | 基于学生授权事实生成的版本化学习画像 |

| `draft` | 缺少充分依据、只能查看或编辑、不能发布为正式路径的内容 |

## 2. 产品总体描述

### 2.1 产品定位

智能学习规划助手面向计算机专业低年级学生，根据其学习目标、当前基础和时间预算，生成满足先修关系与时间约束的学习路径。系统通过诊断、打卡和测验持续更新掌握度，并在测验未达标、多次未完成任务或时间预算变化时调整路径。

系统同时通过千问原生联网搜索补充最新公开资料，通过本地 RAG 保留课程专属依据。两项证据都进入来源校验，联网结果不得仅凭模型记忆生成。

教师通过学生班级投影和班级画像观察学习进度、共性薄弱点与风险，并向全班或指定学生布置独立任务。系统不是替代教师的自动教学系统，教师任务也不直接修改 AI 路径。

### 2.2 用户类别

| 用户类别 | 类型 | 主要职责 | 访问边界 |
| --- | --- | --- | --- |
| 学校管理员 | 平台管理角色 | 创建、停用和重置教师与学生账号；管理平台级配置 | 可访问学校账号管理，不默认查看学生学习详情 |
| 学生 | 核心产品用户 | 创建目标、完成诊断、接受路径、打卡、提交测验、完成教师任务、查看重规划 | 只能访问本人数据和已加入班级的教师任务 |
| 教师 | 核心产品用户 | 创建班级、生成邀请码、查看本班进度、布置和撤回教师任务、查看提交 | 只能访问本人负责班级的数据 |
| 数据与模型维护人员 | 项目次要角色 | 导入课程资料、维护图谱和题库、配置千问模型、维护 API Key、评估搜索质量 | 使用管理工具或 CLI，不作为独立教师端 |

本期实现教师端和多用户权限体系；不实现跨学校多租户、同一班级多教师协同授课、家长端和学生社交。

### 2.3 运行环境

- 操作系统：Windows 11 64 位。
- 后端服务：FastAPI 监听本机 `127.0.0.1:8000`。
- 前端：React、TypeScript、Vite。
- 数据存储：SQLite 与 Chroma。
- 云端模型：阿里云百炼/DashScope 千问 API，默认 `qwen-plus`。
- 联网搜索：千问原生联网搜索能力。
- 现场演示必须能够访问 DashScope API 和互联网，并配置有效 API Key。
- 账号认证采用本地用户名/密码和会话，不接入学校统一身份认证。

### 2.4 约束与假设

- 开发周期约 10 周，团队规模固定为 2 人。
- 平台为单学校部署，支持多教师、多班级；不提供跨学校租户。
- 管理员创建教师和学生账号，教师创建班级并生成邀请码。
- 首个管理员账号由初始化脚本从环境变量创建，不设置硬编码默认密码。
- 学生可加入多个班级；教师可负责多个班级；同一班级只有一个负责教师。
- 教师只能访问本人负责班级的数据；学生只能访问本人数据和已加入班级的任务。
- 教师任务为一次性任务，可关联知识节点，但不直接修改 AI 路径节点。
- 登录使用本地账号密码，不接入学校统一身份认证。
- 模型由千问云端 API 提供，本系统不训练、微调或部署生成模型权重。
- 现场核心演示必须联网；断网时明确失败，不得伪造最新资料。
- API Key 只由服务端从环境变量或本地密钥文件读取。
- 用户学习数据只向云端发送完成任务所需的最小内容，并在首次使用前展示隐私说明。
- 课程资料必须具有合法使用权限，支持 Markdown、TXT 和文本型 PDF。
- 扫描版 PDF 和图片 OCR 不在当前版本范围内。
- 允许预置已审核课程资料和本地索引，但联网搜索结果必须由现场请求获得。
- 时效性声明须通过声明级新鲜度核验；近期事件默认窗口为 30 天。
- 现场不允许使用预生成路径、缓存规划响应、固定重规划结果或预先录制的核心交互。

### 2.5 产品边界

#### 2.5.1 本期范围

- 创建、查询、更新和归档多个学习目标。
- 自然语言目标解析和目标人工修正。
- 个性化诊断、掌握度初始化和学习者画像。
- 课程资料导入、混合检索、真实引用和内容可信级别。
- 知识节点、技能节点、先修关系、题库映射和 DAG 校验。
- 路径生成、时间分配、硬约束校验、解释和候选方案。
- 学习任务、打卡、测验证据、BKT 更新和重规划。
- 千问云端模型调用、原生联网搜索、Web 证据保存、来源校验和模型配置管理。
- 四智能体协作、工具调用记录和运行轨迹展示。
- 单次现场连续演示六阶段闭环。
- 管理员、教师和学生登录与角色权限。
- 教师创建多个班级、生成邀请码和学生加入班级。
- 教师班级总览、学生详情、任务布置和提交查看。
- 教师任务计入学习负荷并触发重规划建议。
- 学生本人画像、教师班级画像、画像版本、统计窗口、数据质量与刷新历史。

#### 2.5.2 非目标

- 不接入真实教务系统或学校统一身份认证。
- 不实现跨学校多租户、同一班级多教师协同授课、家长端和学生社交。
- 不建立自有网页爬虫或大规模网页语料库，联网公开信息由千问搜索返回。
- 不提供正式学分、成绩单或学校教务认证。
- 不训练、微调或部署生成式基础模型。
- 不保证互联网搜索结果的权威性；无法支撑具体声明的来源只能产生 `draft`。
- 不提供断网状态下的实时更新能力。
- 不实现生产级集群、高可用和云部署。
- 不实现代码沙箱执行；代码题自动运行与判题属于后续演进。

## 3. 核心业务闭环

### 3.1 闭环定义

系统必须支持以下连续业务链：

`定目标 -> 诊断起点 -> 生成路径 -> 执行打卡 -> 证据验收 -> 重排闭环`

每个阶段必须产生结构化数据、持久化状态和可查看的 Agent 或规则处理记录。

教师端必须支持以下连续业务链：

`登录 -> 查看班级进度 -> 布置任务 -> 学生提交 -> 教师查看进度`

### 3.2 定目标

**前置条件：** 学生已进入本地系统。

**输入：** 自然语言学习目标；可选技能目标、当前基础、截止日期、每周时间、每日最大时间、学习偏好和课程资料。

**输出：** 结构化 `GoalSpec` 和目标记录。

**通过条件：** 目标可映射到至少一个已有或已校验的候选技能节点；时间字段合法；约束可被路径规划器读取。

**失败处理：** 无法解析时保留用户输入，指出缺失或冲突字段，并要求补充或人工修正，不得创建可发布的正式路径。

### 3.3 诊断起点

**前置条件：** 已存在有效 `GoalSpec`。

**输入：** 目标子图、关键知识节点、题型和难度配置。

**输出：** 诊断题集合、作答记录、初始掌握度和置信度。

**通过条件：** 每个目标关键节点具有初始估计；低置信度节点被标记；题目映射到有效知识节点。

### 3.4 生成路径

**前置条件：** 已完成诊断并生成学习者快照；新主题先在候选区构建可诊断子图，再生成诊断。

**输入：** 目标、掌握度、先修关系、预计学时、时间预算、截止日期、本地数据库记录、本地 RAG 证据、按需联网搜索结果和模型候选路径。

**输出：** 知识覆盖结果、缺失项、主学习路径、候选替代方案、任务排期、风险分、解释、本地引用、联网引用、来源发布时间和抓取时间。

**通过条件：**

- 生成前存在一次可追溯的 `KnowledgeCoverageResult`。
- 非时效性且本地覆盖完整时，不得调用联网搜索。
- 除仅上传资料模式外，可检索缺失或尚未完成本次时效核验时联网；结构错误先修复，预算不足返回冲突。联网后重新检查并遵守两轮上限。
- `verified` 节点均有真实本地或联网引用。
- 时效性声明通过声明级新鲜度核验并关联本次搜索来源。
- 硬先修无冲突，路径无重复节点。
- 学时、每日负荷和截止日期满足约束。
- `draft` 内容不能发布为正式路径。
- 不可行时必须返回冲突原因和可行替代方案。

### 3.5 执行打卡

**前置条件：** 学生已接受路径，且任务处于可执行状态。

**输入：** 任务 ID、实际时长、完成状态、完成比例、困难程度和可选备注。

**输出：** 打卡记录、执行偏差和任务状态。

**通过条件：** 时间与完成比例合法；重复请求不重复写入；应用重启后记录不丢失。

### 3.6 证据验收

**前置条件：** 学生已选择可验收任务或知识节点。

**输入：** 题目 ID、答案、作答时间和幂等键。

**输出：** 得分、证据记录、掌握度变化、薄弱节点和是否触发重规划。

**通过条件：** 题目可映射到知识节点；评分规则可重复执行；重复提交不重复更新 BKT。

### 3.7 重排闭环

**前置条件：** 已产生新的测验证据、执行偏差或时间约束变化。

**输入：** 当前路径、最新掌握度、打卡记录、时间预算和触发事件。

**输出：** 原路径与新路径差异、变更原因、涉及证据、新完成日期和用户影响。

**通过条件：** 未完成的硬先修不被破坏；新路径不超出更新后的预算；调整必须形成 `ReplanEvent`。

### 3.8 教师干预闭环

**前置条件：** 教师已登录并负责至少一个班级。

**输入：** 班级、学生范围、任务标题与说明、截止时间、预计学习时长、可选知识节点和资料链接。

**输出：** 教师任务、学生任务分配、学生提交和教师查看状态。

**通过条件：** 教师只能操作本人班级；任务可发布给全班或指定学生；任务独立于 AI 路径；教师任务计入负荷并可生成重规划建议。

### 3.9 画像刷新闭环

**前置条件：** 学生存在目标、诊断、学习行为、证据、任务或班级关系中的至少一项有效数据。

**输入：** 学生授权事实、班级授权投影、统计窗口、领域事件水位和画像规则版本。

**输出：** 学生画像快照、教师班级画像快照、数据质量说明、风险原因和刷新事件。

**通过条件：** 事件水位变化后旧快照被识别为过期；新快照使用确定性规则复算；教师班级画像只包含本班授权投影。

## 4. 外部接口和界面需求

### 4.1 平台页面

| 页面 | 必需内容 | 主要操作 |
| --- | --- | --- |
| 登录 | 用户名、密码和角色提示 | 登录、退出 |

### 4.2 API 要求

- 基础路径统一为 `/api/v1`。
- 请求和响应使用 JSON。
- 时间使用 ISO 8601，服务端保存 UTC，界面显示本地时区。
- 所有业务接口必须具有请求和响应 Schema。
- 错误响应必须包含 `code`、`message`、`details` 和 `trace_id`。
- 重复打卡、重复测验和重复接受重规划必须支持幂等。
- 前端不得直接访问 SQLite、Chroma、DashScope API 或 API Key。
- 所有受保护接口必须校验会话、角色和班级/学生对象归属。

### 4.3 模型与搜索接口

- 系统只能通过 LLM Gateway 调用千问云端模型。
- 联网搜索必须通过千问原生搜索能力发起，搜索查询和来源写入本地记录。
- 规划前必须执行KnowledgeCoverageChecker并保存覆盖结果；新主题候选骨架/题目构建不受完整覆盖前置限制。
- 非时效性且本地完整时不得搜索；可检索缺口或本次时效核验未满足时按门控搜索，最多2轮，遵守仅上传资料选择。
- 联网证据合并后必须重新执行覆盖检查。
- LLM 输出不得直接写入业务数据库。
- 路径生成结果必须先经过 Schema、本地/联网引用、时效、图谱和约束校验。
- 每次 Agent 工具调用必须写入 `agent_steps`。
- 每次模型生成必须记录云端模型配置、搜索开关、提示词版本、请求时间和运行 ID。

### 5.2 目标和诊断规则

- 同一学生可以拥有多个目标，目标之间共享课程资料和画像，但路径、证据和重规划历史必须按目标可区分。
- 修改已生效目标的时间预算或截止日期时，必须创建新版本或触发重规划，不覆盖旧路径。
- 诊断必须覆盖目标关键节点；无法覆盖的关键节点必须标记为低置信度。
- 诊断题必须映射到有效知识节点，无法映射的题目不得影响 BKT。
- 诊断重测不得删除历史作答，新结果应生成新的掌握度快照。

### 5.3 内容、图谱和路径规则

- 模型可以生成候选知识节点、先修关系和任务，但不能决定最终路径是否可行。
- 生成计划前必须查询本地数据库、知识图谱和 RAG，并由 KnowledgeCoverageChecker 判定数据是否完整。
- 覆盖检查至少包含目标技能、知识节点、硬先修、预计学时、验收题和真实证据六类项目。
- 缺失原因必须使用结构化 `gap_type` 表示，包括目标映射、节点、先修、学时、题目、证据、时效和图结构问题。
- 非时效性目标在本地 `is_complete = true` 时不得联网搜索。
- 除仅上传资料模式外，可检索缺失或本次时效核验未满足时按门控联网；结构/预算错误进入修复或不可行，合并后重新检查。
- 用户明确选择“仅使用上传资料”时可以关闭联网，但缺失项或时效性内容只能标记 `draft`。
- “检查 -> 搜索 -> 合并”最多执行 2 轮，仍不完整时返回 `draft` 和未闭合缺口列表。
- 最新或时效性声明必须来自本次联网搜索，不能使用模型记忆或旧缓存替代。
- 每个 Web 引用必须包含 URL、标题、抓取时间和来源域名。
- 时效性声明须通过声明级新鲜度核验；近期事件默认30天窗口，当前版本使用匹配官方文档，无法核实的声明保持draft。
- 官方文档、学校课程页和标准组织资料优先于一般社区文章。
- 硬先修子图必须是无环有向图。
- 每个可规划节点必须具有预计学时；每个 `verified` 节点必须具有至少一条真实本地或联网引用。
- `verified` 判定必须同时满足证据覆盖、来源时效和图谱规则，模型不得自行提升可信级别。
- 路径发布前必须通过 VR-001 至 VR-008。
- 路径不可行时，系统应返回冲突规则、受影响节点、超时量和可计算验证的替代方向；通常提供 1 至 3 种，无法满足时明确说明，例如延长截止日期、降低目标范围、提高学习时间或减少扩展内容。
- 用户接受新路径后，新路径成为当前版本，旧路径保留只读历史。

### 5.4 打卡和测验规则

- 实际学习时长必须大于零；完成比例必须在 `0` 至 `1` 之间。
- 缺勤按计划任务是否完成计算，不按是否打开页面计算。
- 连续两个计划任务到期未完成时，应触发局部重规划判断。
- 选择题和结构化答案由确定性评分规则处理。
- 简答题允许 LLM 辅助形成评分建议，但最终得分必须由版本化评分规则或人工确认产生。
- 代码题在本期作为证据任务，不执行代码沙箱；自动编译和测试属于后续演进。
- 同一作答请求重复提交时，应返回原结果，不重复生成证据或更新 BKT。
- 多次有效作答的合并规则必须版本化并可在界面查看。

### 5.5 BKT 和重规划规则

- 默认掌握阈值如下：
  - 小于 `0.45`：薄弱，必须补强。
  - `0.45` 至小于 `0.75`：进行中，需要继续练习。
  - 大于或等于 `0.75`：达到解锁条件。
- 每次掌握度变化必须保存旧值、新值、证据、参数版本和时间。
- 低于 `0.45`、连续两个计划任务到期未完成、时间预算变化、证据冲突或目标范围变化时，系统应评估重规划。
- 目标技能变化、总时间预算变化超过 30%、多个关键节点持续不达标或局部调整无法满足硬约束时，应执行全局重规划。
- 重规划必须展示原路径、新路径、节点差异、触发原因、规则和证据。
- 用户拒绝重规划时，系统保留原路径并显示延期或未达标风险。

### 5.6 异常和恢复规则

- 非法 JSON 最多自动修复 2 次，仍失败时终止当前节点且不得写入业务表。
- 初次规划失败后最多修复3次，受180秒总时限约束；仍失败时返回不可行原因和替代方案。
- RAG 无有效结果时应扩展查询或降低阈值；仍无结果时标记证据不足。
- 模型超时时应保留最近成功状态，允许从当前节点重试。
- Qwen API 不可达、API Key 无效或配额不足时，应返回明确错误码和可操作提示。
- 联网搜索失败时不得静默改用模型记忆；可以保存或返回明确标注的非实时草稿。
- 云端模型配置切换失败时应回退到上一个已通过评估的配置。

### 5.7 教师平台规则

- 未登录用户不得访问学生、教师或管理员业务接口。
- 管理员可创建、停用和重置教师及学生账号，但默认不查看学生学习详情。
- 教师只能访问本人负责的班级、班级成员、教师任务和任务提交。
- 学生只能访问本人数据、已加入班级和分配给自己的教师任务。
- 邀请码必须具有有效期和最大使用次数，可被教师撤回。
- 教师任务必须包含标题、说明、截止时间、预计时长、目标范围和完成方式。
- 教师任务目标范围只能是本人班级的全部学生或该班级中的指定学生。
- 教师任务独立于 `path_items`，不得直接增加、删除或重排 AI 路径节点。
- 教师任务时长计入每日和每周学习负荷；超过上限时生成重规划建议，学生确认前原路径不变。
- 教师任务状态至少包括草稿、已发布、已撤回；学生分配状态至少包括未开始、进行中、已完成、逾期。
- 学生成功提交打卡、文本或链接后，任务分配进入已完成状态并计入教师进度；提交记录保留供教师查看，普通打卡/文本/链接任务完成不以教师审批为前提；涉及主观测验掌握证据时须有有效rubric评分，待复核不更新BKT。
- 教师只能查看与班级课程或教师任务相关的答题结果和提交，不包含学生未关联本班的私人目标和隐藏备注。
- 登录失败、账号停用、班级归档、任务发布、任务撤回和越权尝试必须记录审计日志。

### 5.8 课程资源与学习活动闭环

FR-042 至 FR-044 补齐平台基础能力，不只是 RAG 后台导入。

1. 教师在本人班级上传 Markdown、TXT、文本型 PDF，填写标题、说明、来源/使用权限，先存草稿，校验和索引成功后发布；支持下架，历史引用保留授权快照。扫描 PDF 明确提示不支持。
2. 学生可从班级资源列表进入正文/安全下载，或从教师任务进入关联资源与客观练习。资源可以不参与 AI 规划，正常学习链仍可独立完成。
3. 学生主动点击开始/完成阅读，填报实际分钟数；打开网页、停留时间不自动证明掌握。阅读完成、任务完成和知识达标分开显示。
4. 客观题提交后显示得分、正确答案、解析、相关知识点和下一步建议，保存作答与反馈版本。答案和解析在提交前不得出现在前端题目响应中。
5. 简答与代码文本支持提交，但无确定性评分规则时标记 `pending_review`，只显示待反馈，不伪造自动判题结果，也不更新 BKT。教师可按公开版本化 rubric 对本班提交给出人工分数/评语；更正生成新评分版本，BKT 按有效评分重放生成新快照，不叠加旧评分。
6. 学生可查询资源阅读、任务、练习、反馈、实际时长和个人进度；教师仅查看本班授权活动记录。文本/链接任务的提交完成率不等于练习达标率。
7. 单文件默认 20 MiB，单批最多 10 个、总计不超过 100 MiB；正文为空、超限、无权限或解析失败时返回明确原因，不发布半成品。

### 5.9 状态与边界规则

| 对象 | 状态与转换 | 边界 |
| --- | --- | --- |
| 目标 | `draft→diagnosing→ready_to_plan→planning→active→completed`，可转 `archived` | 失败记录在运行对象，不抹掉业务状态；修改建立 GoalSpec 新版本 |
| 运行 | `queued→running→waiting_input/succeeded/failed/cancelled` | 重启后过期 running 标记 interrupted 并允许重试；同一运行已提交步骤不重复执行 |
| 路径 | `draft→pending_acceptance→active→superseded`；可 `rejected` | `content_status` 与路径状态分离；同目标最多一个 active 版本 |
| 学习节点 | `locked/ready/in_progress/completed`，补强用 `needs_reinforcement` 标记 | 排序先修满足只代表可以排期；执行时必须先修达到掌握阈值，不能仅打卡解锁 |
| 教师任务 | `draft→published→closed/revoked` | 发布后内容、截止日期与时长冻结；修改须撤回再发新任务并记录关联 |
| 教师分配 | `not_started/in_progress/overdue/completed/cancelled` | 逾期允许补交，保存 late 标记；撤回取消未完成分配并释放剩余负荷，保留历史提交 |
| 资源 | `draft→indexing→published→withdrawn`，失败为 `failed` | 仅 published 且授权资料参与新检索；历史正文只向原授权读者提供 |

- 诊断默认 6 至 12 道客观题，预计 5 至 10 分钟；关键节点多于题数时用先验与低置信度标记覆盖。固定题库确定性抽题先落地，自适应出题可后续优化，不影响 FR-003。
- 初始未测节点 `p_init=0.2`；诊断按题序通过 BKT 更新，不把“正确率”直接当概率，也不为未作答节点赋高掌握度。重测保留历史，重试题必须生成新 attempt，并换用等价题或先完成补强，防止反复记答案提高掌握度。
- 单选/判断/填空按 0 或 1 形成 observation；多选采用全对计 1、其余 0 的默认规则。需要部分分时另行版本化；未定义 score 到 observation 的映射前不更新 BKT。
- BKT 默认 `p_learn=0.2, p_slip=0.1, p_guess=0.25`，节点/题型可覆盖并记版本。先验 0.62 的错误作答更新为约 0.342939，可触发 0.45 补强线；错误作答不保证任何先验下都下降，测试需指定参数与输入。
- `0.45≤p<0.75` 继续练习，`p≥0.75` 且证据有效才解锁；打卡、阅读、链接提交均不直接提高 BKT。目标完成要求目标知识点全部达标且验收通过，不能只看打卡率。
- “连续未完成”指同目标连续两个计划任务的截止时间已过且完成比例不足 1；由每日检查或访问时惰性检查判定，按事件唯一键只触发一次，不能靠重复提交未完成记录累计次数。
- 补强在原知识节点下新增具有独立 task_id 的练习任务，保持 `(path_id, knowledge_node_id)` 唯一。已经完成的任务和旧路径不可改；新证据使已完成节点掌握度不足时创建补强任务并重新锁定依赖节点的执行，不删除历史完成事实。
- 拒绝重规划保留旧路径，但低掌握度的后继仍被执行规则锁定，并显示预算/延期风险。接受陈旧预览先复查 mastery、目标、成员与负荷版本，变化则返回 409。
- 每次新的 AI 业务请求创建 run；同一 actor+scope+幂等键返回原 run/result，不能为了“现场无缓存”破坏幂等。自动化回放/Mock 可用于测试，但不得当成真实云端现场成功证据。

### 5.10 全局预算与教师统计口径

学生画像保存唯一的全局日/周学习预算，各目标 weekly_hours 为该目标预算上限，不是每个目标都可重复占用全局预算。默认按学生时区自然周周一至周日，UTC 存时间；只有明确允许的学习日才提供时间窗口，不自动结转上周空闲时间。

排期以整数分钟计算：当日剩余容量 = 日上限 − 当日已记录实际分钟 − 当日未完成任务剩余预约分钟；负值视为冲突，不截断后伪装可行。周容量同理。教师任务先在截止前占用可用窗口，所有 active 目标联合排期；AI 任务不足时生成建议，不能挤掉教师任务或超预算。预计与实际不能对同一份工作重复计算；任务完成后由实际时长替换剩余预约。一个学习事件有唯一 ID，同一任务在多个视图出现只计一次。

| 指标 | 定义 | 空值与权限 |
| --- | --- | --- |
| 教师任务完成率 | 已提交完成的分配数 / 已发布且未撤回任务的分配数 | 包含逾期未交；分母 0 显示“暂无任务”，不写 0% |
| 按时率 | `first_completed_at≤due_at` 的完成分配数 / 已完成分配数 | 逾期补交算完成但不算按时；保留首次完成时间 |
| 逾期人数 | 截至统计时点有 due_at 已过且未完成/未取消分配的 distinct student_id 数 | 已补交学生不再算当前逾期，历史逾期另列 |
| 实际学习时长 | 授权范围内非重复学习事件的 actual_minutes 之和 | 不把计划时长当实际；同一个提交关联阅读记录时按源事件去重 |
| 掌握度分布 | 本班有有效评分证据的学生—知识点快照分布 | 无证据显示未知；不使用私人目标/其他班证据推断本班成绩 |
| 风险学生 | 存在逾期、最近有效班级测验 p<0.45，或联合负荷冲突 | 必须显示具体原因和观测时间，缺证据不等于薄弱 |

全班任务在发布时间快照生成分配，后来入班者不自动补发；需要时教师创建补发任务。退班/移除使未完成分配 cancelled，已完成记录保留且只在原班历史授权范围展示；班级归档后只读、撤销邀请码并停止新提交。统计读取成功提交后的最新事务结果，不返回尚未失效的旧缓存冒充即时变化。

### 5.11 资源授权与数据可见性

- 资料所有者、可见范围和可发送云端权限分别保存。范围为 `school`（管理员发布共享资料）、`class`（教师班级资料）、`private`（学生私有上传）。学校内登录不自动获得所有资料权限。
- 目标默认私有；学生可以显式绑定一个当前所属班级，取消关联后教师详情不再显示该目标。教师学生详情只返回班级授权投影，不调用学生全量 profile 接口。班级历史练习记录按授权留存。
- 全局掌握度可供学生本人跨目标规划；教师统计只读取带本班证据来源的快照，不泄露其他班或私人目标的推断结果。
- RAG 在召回前按 actor、scope、membership 过滤，引用详情、下载、Web 证据、Agent 轨迹和发送云端前再次授权。学生私有上传可自助完成，不等同管理员维护的共享课程库。
- 管理员可维护共享课程资料、账号、图谱和云端配置，但默认无权阅读私人学习原文。模型/配置激活与评估仅管理员，学生仅查看必要的模型说明；API Key 永不返回。
- 停用账号、重置密码立即撤销其全部会话；学生不能查询同班其他学生的个人详情，学生查询班级接口只返回班级概况和本人关系。
- 私有/班级资料缺少云端使用授权时，不送入云端生成或嵌入服务；只做本地解析/关键词检索或保持待授权状态，不能把原文先发送再提示。

### 5.12 声明级时效与搜索退出条件

30 天是项目对“近期事件”的默认规则，不是课程要求或供应商能力承诺，也不适用于所有固定知识。

| 声明类型 | 通过方式 |
| --- | --- |
| 固定概念，例如递归定义 | 授权教材/课程依据即可，不要求 30 天内发布 |
| 当前版本/API 行为 | 本次检索匹配版本的官方文档或发布说明，保存版本、访问时间和支持片段；滚动文档无发布日期可核验版本，不编造日期 |
| 最近发布/近期事件 | 来源日期须在 `[requested_at−30天, requested_at]`，可按用户明确时间窗调整并记录 |
| 无法确定时效或声明支持 | 标记该声明 `draft`，不把整份固定知识资料一律判旧 |

搜索返回日期可为 null；`retrieved_at` 表示获得供应商结果的时间，只有确实访问正文才写 `fetched_at`。本次查询条件和供应商实际返回的查询分别保存，未暴露内部查询时为 null，不能杜撰。网页仅有标题/URL 不足以证明声明正确，必须核查片段是否支持具体内容。

覆盖门控采用 `local_complete/is_complete/current_search_satisfied/search_round` 四类状态，避免因 time_sensitive 恒为真重复搜索。新主题允许先构建候选骨架和题目再检查；正式发布仍需输入齐全及确定性审查通过。结构环/非法学时先修复，时间不足返回不可行，不能搜索两轮假装已解决。

### 5.13 学生画像与班级画像规则

学生画像快照至少包含：

- `learning_context`：活动目标、班级关系、全局时间预算和学习偏好。
- `learning_behavior`：实际学习分钟、任务完成率、按时率、最近活动时间和资源阅读记录。
- `mastery_state`：已掌握、进行中、薄弱、未知知识节点及掌握阈值版本。
- `evidence_quality`：有效证据数、来源覆盖、待复核数量、最后更新时间。
- `risk_summary`：风险等级和结构化原因；缺少证据不得推断为薄弱。
- `data_quality`：统计窗口、数据水位、完整度、可用状态和规则版本。

班级画像快照至少包含：

- `class_scope`：班级、负责教师、统计窗口和规则版本。
- `participation`：活跃学生数、有证据学生数和覆盖率。
- `task_metrics`：完成率、按时率、逾期学生数和分母说明。
- `learning_time`：非重复实际学习时长汇总。
- `mastery_distribution`：本班有效证据产生的知识点掌握度分布。
- `common_weak_nodes`：有足够班级证据支持的高频薄弱知识点。
- `risk_students`：风险学生数量、具体原因和观测时间。
- `data_quality`：缺口、样本不足和快照是否过期。

刷新与历史规则：

- 画像由领域事件触发；刷新事件记录 `scope_type`、`scope_id`、`trigger_type`、`source_event_id`、状态和快照 ID。
- 读取时比较快照 `source_watermark_json` 与当前数据水位；不一致时将快照标记为 `stale` 并生成新版本。
- 学生可以查询本人完整画像及历史版本。
- 教师只能查询本班班级画像和本班学生授权投影；跨班或私人目标访问被拒绝。
- 画像数值、比率、风险原因和时间必须由确定性规则计算；LLM 只能生成解释文本，不得修改或补造画像字段。
- 无分母时显示“暂无数据”，不以 0% 或 0 分钟冒充真实观测。

## 6. 数据需求

### 6.1 核心数据实体

系统至少应持久化以下数据：

- 用户和学习者画像。
- 学生画像快照、班级画像快照、画像刷新事件和统计水位。
- 管理员、教师和学生账号、角色和账号状态。
- 班级、班级成员、邀请码和教师负责关系。
- 教师任务、学生任务分配、提交和教师查看状态。
- 登录、权限变更、任务发布/撤回和越权尝试审计日志。
- 学习目标、结构化 `GoalSpec` 和目标版本。
- 知识节点、技能节点、先修边和题目映射。
- 课程文档、文档片段、向量索引和引用元数据。
- 诊断题、诊断作答、测验题、测验作答和评分结果。
- 学习路径、路径节点、学习任务、打卡记录和证据。
- BKT 参数、掌握度快照和重规划事件。
- Agent 运行、Agent 步骤轨迹、云端模型调用和联网搜索记录。
- 知识覆盖检查结果、缺失项、搜索轮次和判定时间。
- 生成内容、可信级别、引用和提示词版本。
- Web 证据快照、来源状态、内容哈希和时效判断。
- 千问模型配置、搜索策略、评估结果和激活状态。

### 6.2 数据完整性

- 主键使用可排序字符串或 UUID。
- 时间以 UTC ISO 8601 保存，界面转换为本地时区。
- 路径发布后不得原地修改，必须创建新版本。
- 课程文档删除采用软删除，已有路径引用仍可查看。
- JSON 字段必须通过应用层 Schema 校验。
- Web 证据必须记录查询、URL、发布时间、抓取时间和内容哈希。
- 云端模型配置必须记录提示词版本和评估结果，未评估配置不得激活。
- 用户答案日志可使用摘要或哈希，避免无必要地保存完整隐私内容。
- 发送到云端模型的数据类别和最小化范围必须写入运行记录。
- 用户密码只保存安全哈希，不得保存明文或写入日志。
- 教师任务不得写入 AI 路径表，任务分配必须指向有效班级成员。
- 教师只能访问本人班级数据，学生只能访问本人数据和分配给自己的任务。
- 画像快照生成后不可原地修改，每次刷新创建新的版本。
- 画像必须保存统计窗口、源事件水位、数据质量和规则版本。
- 班级画像不得引用学生私人目标、其他班级证据或隐藏备注。

### 7.1 性能需求

在目标设备、网络正常且课程索引已建立的条件下：

| 编号 | 指标 | 验收目标 |
| --- | --- | --- |

### 7.2 可靠性需求

- Agent 每个节点具有超时、失败和可重试状态。
- 应用重启后不得丢失已提交打卡和证据。
- 数据导入失败必须事务回滚。
- 重复提交必须幂等。
- 路径生成支持从最近成功节点恢复。
- 云端模型超时、限流和搜索失败时保留最近成功状态并允许重试。
- 模型配置切换失败时自动回退到上一个已通过评估的配置。
- 画像刷新失败时保留上一有效版本并标记 `stale`，不得返回伪造的新版本。
- 会话失效时清理前端身份状态，受保护请求返回 `AUTH_REQUIRED`。
- 现场演示连续运行三次不出现阻断性崩溃。

### 7.3 可解释性需求

- `verified` 节点必须显示至少一条真实资料来源。
- 联网来源必须显示 URL、来源域名、发布时间和抓取时间。
- `draft` 节点必须显示醒目标识。
- 每条路径限制必须对应规则编号。
- 每次重规划必须显示触发原因和前后差异。
- Agent 轨迹必须显示云端调用、联网搜索、工具节点、耗时和校验结果。
- 画像必须显示生成时间、统计窗口、数据水位、完整度和规则版本。
- 画像数值事实不得由 LLM 生成或覆盖。
- 解释文本不得覆盖规则校验失败结论。

### 7.4 安全和隐私需求

- 服务默认只监听本地回环地址。
- 密码只保存 Argon2 或 bcrypt 哈希。
- 登录使用安全会话，修改数据的请求必须校验 CSRF 或同源策略。
- 所有受保护接口必须在服务端校验角色和班级/学生对象权限。
- 教师不得访问非本人班级；学生不得提交他人任务或读取他人进度。
- 班级画像不得包含学生私人目标、其他班级证据或隐藏备注。
- 管理员、教师、学生登录和关键教师操作必须记录审计日志。
- 向千问云端发送的数据必须遵循最小必要原则，并在首次使用前提示供应商和数据类型。
- API Key 只允许服务端读取，不进入前端响应、日志或 Agent 轨迹。
- 上传文件必须限制扩展名、大小和规范化路径，防止目录穿越。
- 不发送未授权课程资料、个人隐私或没有生成必要的完整答题原文。
- 日志不得记录完整密码、密钥或不必要的完整答案。
- Web 证据和模型配置必须具有版本与内容哈希。

### 7.5 可维护性需求

- 前端、API、Agent、算法和数据访问分层。
- 核心算法必须有单元测试。
- 业务接口必须有 Schema。
- 提示词、BKT 参数、千问模型配置和搜索策略必须版本化。
- API 依赖版本和评估问题集必须可复现。
- 数据导入脚本可重复执行。
- FR-001 至 FR-050 应能够映射到设计、接口、数据和测试用例。

### 7.6 可用性需求

- 学生无需开发者介入即可从界面完成六阶段闭环。
- 教师无需开发者介入即可完成班级创建、邀请、任务发布和进度查看。
- 学生可直接查看本人画像；教师可直接查看本班班级画像和刷新时间。
- 长耗时操作必须显示当前 Agent、步骤和加载状态。
- 生成结果提供重新生成和查看原因入口。
- 错误信息必须说明用户可采取的操作。
- 桌面端为主要验收界面；手机端不在本期验收范围。
- 节点颜色不能作为唯一状态表达，必须同时提供文本或图标。

## 8. AI、联网搜索与模型配置需求

### 8.1 千问云端模型

- 默认通过阿里云百炼/DashScope 调用 `qwen-plus`，模型名可配置。
- 推理通过服务端 LLM Gateway 发起，前端不得直接持有 API Key。
- 默认允许按需使用千问原生联网搜索；普通生成请求关闭搜索，只有门控要求检索时启用。
- 路径可行性由确定性算法判断，千问模型不得覆盖规则失败结果。
- 默认单节点推理超时为 90 秒，路径生成总超时为 180 秒。
- API Key、限流、配额和网络错误必须映射为稳定错误码。
- 系统不训练、微调、合并或部署生成模型权重。

### 8.2 联网搜索与时效

- 用户要求最新资料、当前版本或近期变化时，系统必须启用联网搜索。
- 每次搜索必须记录搜索查询、发起时间、来源数量和搜索状态。
- 每条 Web 证据必须包含 URL、标题、来源域名、摘要、发布时间、抓取时间和内容哈希。
- 官方文档、学校课程页和标准组织资料优先于一般博客或社区文章。
- 时效性声明须通过声明级新鲜度核验；近期事件默认窗口为 30 天。
- 来源不可访问或无法支持具体声明时，相关内容标记 `draft`；发布时间缺失不等于资料过期，按声明级规则判定。
- 搜索结果为空时允许扩展查询；仍为空时不得使用模型记忆冒充最新信息。
- 系统必须保留搜索失败和来源不可访问的记录。

### 8.3 云端模型配置

模型配置至少包含：

| 配置 | 要求 |
| --- | --- |
| 供应商 | 阿里云百炼/DashScope |
| 模型名称 | 默认 `qwen-plus`，可版本化切换 |
| 搜索开关 | 默认允许，单次调用由覆盖门控决定 |
| 搜索参数 | 结果数量、来源过滤和时效范围 |
| 生成参数 | 温度、最大输出和超时 |
| 提示词版本 | 每次运行必须记录 |
| 评估结果 | 未通过评估不得激活 |

配置切换必须保留旧版本。新配置鉴权或评估失败时恢复上一可用配置。

### 8.4 AI 与搜索质量门槛

- JSON Schema 合法率不低于 95%。
- 联网回答引用存在率必须为 100%。
- 时效性声明的新鲜度合规率必须为 100%。
- 搜索来源可访问率不低于 95%。
- 路径硬先修冲突率必须为 0。
- 在 20 个未预先配置的目标中，至少 80% 可生成通过规则校验的路径。
- 在本地数据完整的非时效性测试目标中，联网搜索调用次数必须为 0。
- 在缺失数据测试目标中，必须识别缺口、触发搜索并在合并后重新检查。
- 搜索不可用时必须返回明确错误或 `draft`，不得伪造最新资料。

## 9. 验收需求

### 9.1 现场闭环验收

`AT-015` 是最高优先级现场验收场景。验收必须在一次连续会话中完成：

1. 确认演示数据处于可重复的初始状态、网络可访问且 API Key 有效；如系统提供一键重置，则只重置业务数据并保留课程资料、索引和千问模型配置。
2. 学生现场输入包含缺失知识项或时效性检查的新目标、截止日期、每周时间和每日时间。
3. 系统现场解析目标并生成诊断题。
4. 学生提交诊断答案，系统生成初始掌握度和学习者快照。
5. 系统先检查本地覆盖结果；存在缺失或时效性要求时调用千问联网搜索，合并后重新检查并生成知识框架、候选路径、风险和本地/联网引用。
6. 学生查看证据并接受一条 `verified` 路径。
7. 学生提交一次学习打卡。
8. 学生提交一份预先设计但不属于缓存响应的未达标测验答案。
9. 系统现场更新 BKT，展示掌握度下降、补强任务插入和后续任务顺延。
10. 学生预览并接受重规划，系统展示原路径与新路径差异。
11. 评审能够打开 Agent 轨迹，确认目标解析、联网搜索、本地检索、规划、校验、BKT 和重规划均产生本次运行记录。

**通过条件：**

- 所有步骤在单次会话中连续完成。
- 路径、重规划和最新信息来源不是预生成或缓存结果，核心请求具有现场时间戳和新的运行 ID。
- 现场能够展示覆盖检查前后结果，证明搜索由缺失项或时效性条件触发。
- 至少一个知识点展示真实本地引用，至少一个时效性声明展示本次联网来源。
- 至少一个硬先修冲突场景被规则校验阻止或修复。
- 至少一次测验未达标触发补强和重规划。
- 无阻断性崩溃、手工改库或开发者替用户操作。

### 10.3 范围压缩顺序

时间不足时按以下顺序压缩：

1. 模型管理页面的辅助筛选和视觉优化。
2. 非核心泛化目标的完整闭环，仅保留结构化生成测试。
3. 非关键 Agent 轨迹的可视化细节。
4. 演示数据的高级管理能力。

以下内容不得压缩：

- 单次现场六阶段闭环。
- 真实本地 RAG 与联网搜索引用、来源时间和可信级别。
- 硬先修和预算规则校验。
- 测验未达标触发 BKT 与重规划。
- 千问云端模型调用和现场联网搜索。
- 管理员、教师、学生角色权限、班级邀请、教师任务和进度查看。
- 学生画像、教师班级画像、快照水位、刷新历史和隐私投影。

## 12. 需求基线结论

本项目以第 8 实践周验收为交付目标，交付一套单学校、多教师、多班级的智能学习规划平台。系统必须先检查本地数据库和 RAG 覆盖，缺失时才通过千问原生联网搜索补充，再重查、生成和校验学习计划；学生画像是学生授权事实的版本化聚合，教师班级画像是本班授权投影的版本化聚合；教师端通过角色权限和班级隔离查看画像并布置独立任务。

现场验收的核心不是单独展示页面或模型输出，而是证明系统能够在一次连续会话中，由现场输入触发目标解析、联网搜索、诊断、路径生成、打卡、未达标测验、掌握度更新、补强任务和路径重规划。任何依赖预生成搜索结果、缓存路径或人工改库的演示均不满足本规格。

## 实现契约补充索引

资源与运行状态、权限数据、接口、BKT/评分去重、预算接受事务、云端能力限制、统计与评测分母，统一见[技术设计第20节](2026-10-27-smart-learning-planner-technical-design.md)。其中20.8补齐新主题候选→诊断路由与持久事件，20.9给出资源链、重复作答、统计与预算手算测试规格。这些是待执行的验证条件，不是运行结果。

搜索策略：仅可检索的资料/知识缺口触发搜索；结构错误先修复、预算不足返回冲突。普通非时效性生成可使用已授权本地资料（包括已审核Web快照）；时效性和现场指定联网场景必须产生本次来源，不能将历史快照冒充新搜索。用户选择仅上传资料时，有充分本地固定知识依据仍可verified，缺失部分draft。

核心字段统一为 target_skill_ids；候选生成可先于覆盖完整，正式排期与发布不得先于完整覆盖和规则通过。EvidenceItem统一引用本地chunk或Web evidence ID，不强制所有网页伪装chunk_id。已完成任务与已发布结构只读，执行状态由事件投影，新补强用独立任务保存。

### 子功能验收组织

每个SF编号至少关联一个正常行为；涉及权限、版本、上传、评分、预算和重试的条目增加相关异常。验收记录使用SF编号、关联FR/AT、前置身份与数据、操作输入、预期、实际、版本及证据。新增行为不能仅凭原AT通过即宣称完成；原AT继续保留，SF补充具体检查。

第三周优先AUTH/ACCOUNT/CLASS、RESOURCE基础文本、TASK/ASSESS客观链与记录；第四周完善这些模块并集成GOAL/DIAG/PATH/REPLAN/PROFILE/AI。未接入条目标部分或未完成，第五周补齐必做分支，不由本清单推断两周内全量完成。
